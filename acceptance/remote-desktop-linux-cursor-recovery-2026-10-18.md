# Linux 正式窗口光标与快速锁屏恢复

日期：2026-10-18。产品基线 `478fcfe`。本轮对应 W2/W5；不是完整首版或系统密码登录验收。

## 首轮实机结果（修复前）

Windows 隔离 Desktop 经既有认证连接 Ubuntu 22.04 / GNOME Wayland / VMware 单屏（1314×704）。Linux 使用临时 runtime service drop-in 和受 supervisor 管理的 helper；本机安装版未更新。

普通桌面正式独立窗口显示自有 GTK 测试夹具。四个区域依次设置箭头、24×24 青色光标、文本光标和透明隐藏光标。移动经拥有的原生窗口 WM_MOUSEMOVE 进入产品输入通道，不是全局物理鼠标注入。夹具收到四个位置，和窗口留白/缩放换算相符（最大误差不足 0.002 逻辑像素）；没有发送点击，夹具点击、释放计数均为零。

青色光标显示区域含 900 个精确 RGB(0,240,220) 像素，符合 1.25 倍窗口缩放后的独立光标合成。文本和隐藏区域的截图已保存，尚未完成像素判定，不据此宣布形状/隐藏验收通过。

两次快速锁屏和一次解锁均由同一个窗口自动恢复，没有手动重试；每次获得新会话并恢复到仅查看：

| 转换 | 本机观察耗时 | 结果 |
| --- | --- | --- |
| 首次锁屏 | 2.486 秒 | 画面恢复；光标缺失 |
| 解锁 | 2.528 秒 | 画面、移动输入恢复；原青色区域光标像素为零 |
| 再次锁屏 | 2.460 秒 | 画面恢复；光标缺失 |

耗时由操作端同一单调时钟测得，包含远端命令提交和状态轮询开销，不是纯媒体延迟。测试机时钟存在偏差，未直接相减跨机时间戳。解锁使用授权的会话恢复命令，不等同于密码登录。

第二次锁屏明确等待启用操作及输入 worker 就绪，再发送移动。只读 DRM 探针在窗口仍打开时读到 32/32 次可见 64×64 光标，热点位置 (328,352)，与预期输入 (328.035,351.891) 一致；fd 无增长。此时窗口截图没有对应光标，说明不能将问题归咎于系统没有光标或移动未送达。

## 定位与后续

Bridge 在打开采集之前读取环境里的可选光标能力。helper 在会话切换时退役并重新注册，这一间隙会返回无光标能力。随后视频采集可正常启动，但窗口继续保留之前的结果，因此跳过独立光标流。

新增真实 loopback QUIC 回归使用生产 DesktopHost/Client，模拟启动采集前无能力、启动后支持光标。修复前确定失败（期望 true，实际 false）。Bridge 现保留原设备兼容性检查，在视频 Ready（服务端已成功启动采集）之后重新查询可选光标能力。能力查询失败时保留视频/输入，也不沿用旧 helper 的能力；无新增协议字段或认证流程。每次打开增加一次现有环境请求，使用既有请求超时。

四项定向测试通过：能力启动后出现、替换为旧版/未知版本、可选查询失败不破坏视频和旧请求、旧设备在任何桌面流之前被拒绝。完整 Bridge **99 项测试通过**（17.43 秒）。测试 fixture 不证明原生画面或系统登录，后者另见下述实机结果。

## 修复后正式窗口复测

Linux Desktop/Executor 保持首轮二进制不变，只重新构建 Windows 操作端，SHA256 `0b33e2c964122d76049cb49b53be9814de269ca4eb2e103f01fa4fb1e7e808f5`。完整构建 4 jobs、4 分 31 秒；没有并行 Linux 编译。

- 初始普通桌面青色光标：900 个精确青色像素。
- 快速锁屏：同一个父窗口自动恢复，观察耗时 **2.602 秒**，新会话回到仅查看；启用操作后移动到远端 (328.035,351.892)，窗口内箭头可见。独立只读 DRM 探针 32/32 次可见，热点 (328,352)，图像哈希与修复前相同，无 fd 增长。
- 解锁：同一窗口 **2.568 秒**自动恢复并保持仅查看；启用操作后移动回青色区域，再次取得 **900 个精确青色像素**。
- 解锁后继续切换箭头、文本和隐藏区域：夹具收到相应位置和形状，均无点击或按住状态。80×80 目标邻域的高亮像素分别为 96、33、0；隐藏邻域只有一种背景颜色。已目视核对锁屏箭头和普通文本光标。这个隐藏结果只代表 GNOME Wayland 的夹具，不覆盖 X11 的 XFixesHideCursor 缺陷。
- 本轮没有手动重连、追加锁屏稳定等待或修改远端产品二进制。因此该能力查询时序缺陷有修复前失败、修复后成功证据；整体光标交付条目仍有其他平台和多屏待验收。

修复后原始记录：`.build/remote-desktop/formal-linux-login-9559aa9dac0f`、`.build/remote-desktop/assistance-product-2760a617312b`，汇总见同名 JSON。

结束时测试脚本直接调用 WebView 的 `window.close` 被已有 capability 拒绝；未修改权限或重试该调用，改用测试启动器既有 stop 标记退出拥有的隔离进程。本轮不宣称完成窗口正常关闭验收。随后验证原服务 active、文件哈希保持、会话解锁、无测试进程和输入设备，远端目录已删除；Windows 测试进程退出，七个复制的配置/凭据/密钥文件逐项删除。其余本地证据和缓存保留。

此前原生 worker 紧接锁屏启动的 `Display did not wake` 失败仍保留。此次两次自动恢复通过，不证明那个唤醒问题已修复。X11 系统隐藏、多屏、Mac 源和长期性能均不在本轮通过范围。
