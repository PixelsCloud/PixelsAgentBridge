# AI 远程桌面协助：实现与阶段验收

日期：2026-10-17。分支：`feat/remote-desktop-v1`，实现基于 `afe045d`。
本文只记录 W6 的已验证范围，不代表三平台远程桌面已完成或已发布。

## 实现

- 新增 `pab_desktop_assistance` 的 request/status/wait/cancel，加入现有 Desktop
  工具组。使用现有账号、设备连接和密码，不新增远端认证或网络监听。
- 同一 OS 用户的 operator 目录通过运行时 SQLite 交换请求；服务目录、账号 ID
  与账号修订号隔离。现有只读 MCP 状态上报 WebSocket 不承载窗口命令。
- 主窗口展示原因和期望操作；用户点击后复用/打开独立窗口，保持只查看。窗口
  实际显示首帧后才能进入 active；用户明确点击完成才能进入 completed。
- 请求支持稳定 ID 去重；相同 ID 参数冲突明确失败。读取原请求结果先于重新连接
  设备，因此目标后来离线不会掩盖已接受请求的结果。
- 关闭、断线、重启和心跳失效有独立处理；终态不复活。取消请求不关闭共享窗口。
  账号变化不转交请求，不新增全局自动化锁，也不强制永久添加设备。

详细接口与使用范围见 [协助工具说明](../REMOTE_DESKTOP_ASSISTANCE.md)。

## 已通过的自动化验证

最终实现运行 `cargo test --locked -p pab-bridge --lib --bin pab-mcp -j8`：
Bridge **96** 项、MCP **43** 项通过。其中 8 项存储生命周期测试覆盖实际 SQLite
事务、并发去重、参数冲突、终态重试、账号/服务/请求方隔离、窗口关闭、Desktop
替换、请求方退出、迟到心跳、过期清理及同窗口多请求取消边界。

MCP 参数测试覆盖按 action 的字段约束及有限等待。界面 fixture 的 8 项测试通过，
覆盖既有远程桌面交互，以及提示实际挂载后确认、用户主动打开/拒绝、明确完成和
恢复期间不能完成。最后补充按钮显示具体期望操作，以及同窗口多请求只完成指定
一项的验证。fixture 结果仅证明交互逻辑，不能替代真实原生窗口验收。

前端 TypeScript/Vite 构建通过。Windows 完整 Debug/custom-protocol 构建通过；
所有 Cargo 构建使用 8 jobs，嵌套 CMake 1 job、MSVC `/MP1`，串行执行构建步骤。
Linux 完整 Release/custom-protocol 构建也通过（1 分 54 秒，含最终按钮说明），
产物 45,336,904 字节，SHA-256 记录在相邻 JSON；这只计为编译验证。

## 真实 Windows MCP/Desktop 验收

使用独立且限制访问的用户数据目录，已有登录和设备凭据仅在本机用于测试；没有
替换本机安装版，没有向仓库写入凭据或截图。MCP 使用原认证连接 90，Desktop
使用正式前端和 Tauri 命令；通过仅测试构建提供的 WebView2 CDP 操作提示按钮。

实际通过：无 Desktop 时 waiting/desktop_not_running；启动后提示真实显示并
确认 displayed；用户点击拒绝后 user_cancelled；重复 request 返回同一终态；
wait 等到请求过期；零时长 wait 返回等待中且不取消；AI cancel 生效；请求方退出
后提示消失且结果为 requester_unavailable。全程未打开远端查看窗口，也未发送
远端键鼠。测试进程退出后检查，自有 Desktop/MCP/WebView 进程为 0。

前两次测试修正了 harness 的启动/动画观察：CDP 端口开放不代表主页面已创建，
DOM 可见不代表动画结束及原生 displayed 确认已经返回。保存失败记录并确认请求
终止后，用新隔离目录重跑；最终完整通过。不是靠重试未确定结果的操作来验收。

产物 SHA-256 与结果见 [机器可读记录](remote-desktop-assistance-2026-10-17.json)。
该记录明确绑定实际测试的二进制，后续重建不能自动继承其运行结论。
真实提示验收后仅调整了远程窗口完成按钮的任务说明文字；该调整通过前端构建和
8 项界面测试，未将此前未打开远端窗口的验收记为这项按钮的实机测试。
