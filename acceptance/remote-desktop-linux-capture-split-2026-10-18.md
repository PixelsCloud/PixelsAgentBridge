# Linux 软件编码期间释放采集循环

2026-10-18，基线 `a492ef3`。本轮缩短了 PipeWire 循环锁的占用，**没有解决全部
端到端掉帧**。13 项软件编解码回归与完整 Linux Desktop 构建通过；正式窗口
混合测试首轮仍失败。完整关闭数保持 10/53。原始数据、候选哈希和恢复结果见
[机器记录](remote-desktop-linux-capture-split-2026-10-18.json)。

## 实现

原路径持有 PipeWire 循环锁，完成 BGRA→I420 转换和 OpenH264 编码后才归还
采集池缓冲区。现拆成私有 `prepare_bgra` / `encode_prepared_bgra`：

1. 锁内只转换到编码器原本就拥有的 Y/U/V 平面，随即归还池缓冲区。
2. 锁外编码这些已有平面；不保留采集指针，不增加像素复制或图像分配。
3. 编码结束重新确认采集代次有效，布局变化或断开时不发布旧帧。

硬件路径未新增 CPU 读取；其他平台既有 `encode_bgra` 入口调用同样两个步骤。
准备状态只消费一次，失败转换或转入 NV12 编码会清除旧准备状态。新增用例
验证原始 BGRA 被覆盖并释放后，奇数尺寸编码结果仍与原入口一致；未准备、
重复编码、失败准备及 NV12 切换都不会误用上一张 BGRA。

这样处理是为了在不访问失效采集内存的前提下缩短锁占用。PipeWire 明确指出
流缓冲区的生命周期由流及 `remove_buffer` 事件管理，不能直接解除锁后继续
假定原指针一直有效。[PipeWire 流缓冲区说明](https://pipewire.pages.freedesktop.org/pipewire/page_streams.html)

## 测量

新增手动软件阶段测量与 C++ 采集探针。C++ 探针复用生产 `Capture` 和软件
编解码源码，仅拦截本实验的编码调用以计时；不保存桌面像素或 H.264 数据。
每种光标模式采集 120 帧，排除前 15 帧；无网络、无正式 viewer，不能作为
端到端显示验收。前后各一次顺序短测，环境负载不是严格恒定。

| 原生采集阶段 | 原内嵌光标 | 原独立光标 | 拆分后内嵌光标 | 拆分后独立光标 |
| --- | ---: | ---: | ---: | ---: |
| 转换与编码平均耗时 | 37.52 ms | 37.28 ms | 32.58 ms | 34.38 ms |
| 其中转换平均耗时 | 未分开测 | 未分开测 | 5.13 ms | 5.09 ms |
| 其中编码平均耗时 | 未分开测 | 未分开测 | 27.45 ms | 29.29 ms |
| 原生交付速率 | 14.47 FPS | 14.51 FPS | 14.73 FPS | 14.68 FPS |

锁内图像处理由转换加编码缩为转换部分，但本轮原生交付提升很小，不能宣称
端到端性能已经恢复。纯内存生成色条测量另得到转换约 4.83 ms、编码约
8.76 ms、解码约 3.65 ms；它与真实采集画面复杂度和并行负载不同，不可互换。

完整 Desktop 候选正式混合测试首轮实际显示 **7.85 FPS**，没有无效采样点；
命令、PTY 和 4 MiB 上传下载已完成，随后呈现门槛失败。逐秒实际帧数为
`5,4,4,6,6,6,8,8,10,11`。网络原生对照约 13.19 FPS，确认 90 帧；超过 12，
但未达到该探针的 15 FPS×90% 门槛，仍记失败。下一步检查首次窗口呈现等待
触发拥塞降速的情况，不放宽现有阈值。

混合驱动现保存失败轮本身，并增加采样前后的 CPU、内存及 PSI 数据，避免
只保留成功轮而丢失问题现场。该轮没有执行到视频关闭后的旧业务检查，也
没有达到 30 分钟。首次 C++ 探针因测试启动器关闭 stdin 而立即退出；修正
启动器保持父管道后重测，原失败与显示模式恢复结果保留。

## 构建、资源与恢复

软件回归 13 项通过，手动计时用例默认 ignored；Linux 完整 Desktop 构建通过。
本轮构建配置为 3 jobs，但检测到其他会话启动高并发构建时曾发生预算叠加；
已暂停自有构建，并增加只控制该容器的额度监控，按其他构建占用暂停/恢复。
不能把这一轮描述为始终满足总并发约束。

原生探针没有替换服务，前后服务 PID 相同。正式窗口测试结束后恢复原安装
服务、会话 2（active/unlocked）、1694×1102 显示模式与原 TOML/unit 哈希。
远端测试目录、文件、临时任务、媒体进程和虚拟输入设备清理；本机测试 Desktop
退出，安装版未替换。没有 push 或 COS 发布。
