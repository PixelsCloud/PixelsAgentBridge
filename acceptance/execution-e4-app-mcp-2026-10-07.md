# E4 应用 MCP 入口与 Bridge 记录验收

日期：2026-10-07。基于 `2877f6b`。本轮实现正式工具代码并验证本地进程传输；尚未更新安装包或当前 AI 宿主工具，因此 E8 仍未完成。

## 改动

- 新增 `pab_list_apps`、`pab_launch_app`、`pab_open_file`，放入既有 Desktop 工具组；工具声明、调用分派、分组关闭和失败标记使用同一目录。源码共 68 个工具：core 15、file 15、system 12、desktop 14、Git 8、container 4。
- 三个工具强制 `execution.mode=desktop_user`，使用当前设备连接发现的引用；不能传用户名/密码/服务身份代替。应用目标只接受明确 ID 或路径；列表没有分页，搜索受 UTF-8 字节预算约束；未知参数和混合目标在运行时初始化前拒绝。
- Bridge 使用 v12 能力检查；应用数据类型、计数、原生身份、进程归属和持久化 execution_context 必须一致。旧设备不会接收到不支持的应用请求。
- 复用本地持久化任务和 `pab_get_operation`；活动应用操作计入已有断开检查。重启查询不改身份，同 ID 换参数/连接冲突，终态不被迟到结果回退。
- 明确的应用前置拒绝（无可用执行上下文、不支持的平台、无效请求等）记为 failed；丢回复、格式错误、存储/内部错误仍保留 unconfirmed。Linux 的不支持错误通过协议保留明确代码和提示，避免变成笼统的无效请求。
- 中英文 README、三语任务名称及工具覆盖表同步。修正先前漏记执行账户工具的覆盖表和遗留工具数断言；新工具的安装实测状态保持 `not_run`，没有把源码测试写成线上通过。

## 测试结果

| 环境 | Bridge library | MCP binary unit | 真实 stdio 子进程 | 其他 |
|---|---:|---:|---:|---|
| Windows 本机 | 67/67 | 38/38 | 7/7 | workspace locked check；Desktop TypeScript noEmit 通过 |
| macOS ARM，huayang UID 501 | 67/67 | 38/38 | 7/7 | workspace locked check；原生 Pixels 命令任务 `98bba1eb-ab67-4ab2-9e85-cb6c055d05f0` exit 0 |
| Linux Debian 无 GUI 容器 | 67/67 | 38/38 | 7/7 | Executor 无 GUI 应用拒绝及错误协议测试 1/1，--rm 容器结束 |

新增/扩充覆盖：

1. 工具导出的 schema、68 项目录与覆盖表一致；必选上下文、service/user 拒绝、错误类型、过长中文搜索、未知字段、同传 ID/路径、额外启动参数和 URL 字段拒绝。
2. v11/未知能力拒绝、v12 接受；完成结果不能缺实际身份，不能换账户/会话/数据类型或伪造计数。
3. 应用接受记录为 control，unconfirmed 保留原身份并计入活动操作；重新打开数据库不重放，同 ID 换选择/换 owner 冲突，迟到消息不能覆盖终态。
4. 通过真实 MCP SDK 与子进程验证新工具可发现、缺少 desktop_user/错误模式立即返回结构化错误；禁用分组依旧在联网初始化前拒绝。测试使用隔离数据库，不接触用户保存的设备凭据。
5. 前置拒绝与未知派发结果分类；Linux 服务无需探测 GUI 即明确拒绝桌面应用。

stdio 测试只证明新构建 MCP 的工具发现、解析和传输。没有把当前宿主的旧版工具重命名为新工具，也没有用独立 stdio 代替用户要求的安装后 `pixels.pab_*` 验收。
