## 修复观看窗口的完成操作

同一个观看窗口可先后处理多个协助请求。旧实现把 `finishing` 和完成错误保存在
窗口级状态：请求 A 的完成 IPC 尚未返回，A 已取消/过期、窗口转向请求 B 时，
B 的完成按钮仍被 A 禁用；A 的延迟失败还会替换 B 所在窗口的连接状态。
当前请求失败后重试成功，旧的错误也可能继续留在窗口中。

现在将完成控件按 assistance_id 独立挂载，忙碌和错误状态随该请求生命周期退出。
成功只移除对应 ID；当前请求失败仍在原生画面上方的工具栏显示错误，可以重试。
默认只查看、显式完成、恢复期间禁用完成和已有输入控制保持原有行为。

三个新增回归用例在旧实现全部失败：

1. 旧完成仍挂起时，新请求可以单独完成，旧成功不能误删新请求。
2. 旧完成延迟失败不能污染新请求状态。
3. 当前完成失败可见、可重试；成功后错误退出。

修复后，远程桌面与协助提示共 15 项浏览器测试通过，TypeScript 检查通过。
测试和构建子进程限制到 2 核；负向验证时另一会话 Cargo 使用 6 jobs，合计不超过
10；正向验证时没有其他 Cargo 编译。没有运行安装或覆盖本机产品。

负向测试本身完成并报告 `3 failed`；包装脚本随后因 GBK 无法输出勾叉符号退出。
保存的 UTF-8 日志完整，正向检查已修正包装脚本输出编码，exit 0。

## 真实 Desktop/MCP 生命周期

沿用既有隔离测试目录与已编译 Windows Desktop/MCP，使用已有 Apple 设备认证
建立请求。没有复制新凭据、改账号文件、改服务配置或切换远端服务。全程只验证
本机协助提示，不打开 viewer、不发远端输入。数据库查询仅观察本轮请求。

| 操作 | 实际结果 |
| --- | --- |
| 无 Desktop 时创建请求，再启动 Desktop | 由 desktop_not_running 变为实际显示，仍 waiting；没有自动打开远端窗口 |
| 重复原 request_id 与参数 | 返回同一 assistance_id 和 revision，没有新提示 |
| 强制结束 Desktop，立即启动新实例 | 约 29.28 秒后同一请求重新实际显示；revision 增长，仍 waiting，没有完成结果或旧窗口绑定 |
| 强制结束请求方 MCP，另一 MCP 仍在线 | 约 27.41 秒后仅前者取消，outcome=requester_unavailable；后者提示显示、仍 waiting |
| 另一 MCP 查询前者请求 | 拒绝访问，未混用请求所有权 |
| 已显示请求到达 8 秒有效期 | 状态 expired，提示消失，没有误记 completed |
| 请求方正常关闭 stdin 并退出 | 约 0.59 秒后请求取消，提示消失 |

强制退出场景的延迟来自既有 30 秒参与者租约；这不是即时进程死亡检测。
所有四个请求最终为 cancelled/expired；两个测试 MCP 和两代 Desktop 均退出，
诊断端口 39100、1429 已释放。现有私有目录和数据库保留，未尝试删除此前被自动
审批拒绝清理的数据。没有运行新的本机安装包。
