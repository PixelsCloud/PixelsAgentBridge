# Windows 竖屏正式窗口失败与原生错误采集

日期：2026-10-18。正式窗口失败基线为 `6fa414f`。
原始记录：[JSON](remote-desktop-wgc-formal-failure-2026-10-18.json)。

90 空闲预检通过后，隔离候选正式窗口能够观看主屏；临时副屏位于
(-1080,0)，桌面尺寸 1080×1920，旋转 90 度。切换副屏后 25 秒内没有
恢复到可操作状态，而是重连。未发送鼠标或键盘输入；fixture 计数为零。
本轮不能算竖屏、光标像素或坐标验收通过。

调用方只收到 `unexpected end of file`，没有采集子进程的具体错误。
不能据此判断是 WGC、光标、权限还是其他原因。已恢复原服务与单屏布局，
释放标志为零，自有进程和七个临时任务均已清理，下载文件已核对哈希。

为定位原因，媒体进程现在独立读取非交互 worker 的 stderr，仅保留最后
2048 字节；发生错误时最多等待 200 毫秒并附带诊断。正常帧路径不增加
等待，交互 worker 的二进制事件协议保持原样。进程退出仍按原机制回收。

验证结果：

- Windows 媒体测试 29 项通过，1 项手动性能测试忽略；完整 Desktop 构建通过。
- Linux 媒体测试 31 项通过，1 项手动性能测试忽略；完整 Desktop release 构建通过。
- 实际原生 worker 和完整 Windows Desktop 均以虚构屏幕 ID 验证错误传递，
  能返回 `Selected screen disappeared`，并完成子进程回收。
- 构建使用 Cargo 2 作业、原生构建 1 作业；未更新本机安装版。

这项修正只完成错误诊断能力。90 正式竖屏场景仍需用新候选复测，根因尚未确认。
完整验收保持 11/53，未发布 COS。

## 新候选复测

Desktop SHA256 `956071a6b927c4a6f6fdb170352769079fbd240922262cea5ae0f5d6d5725986`
复现同一竖屏重连；主屏已正常显示，切换后尚未发送输入。
新增诊断返回 `media encoder=nvenc_gpu readback_per_frame=0` 后的
`bad allocation`。这证明采集子进程异常已传回，但尚不能判断具体分配位置
或断言机器内存不足。下一步在 WGC 后备初始化各阶段附带错误上下文。

原服务、单屏布局已恢复，释放标志为零，临时进程及七个任务清理完成；
fixture 与布局日志在进程结束后下载并校验 SHA256。
结构化记录：[新候选原生错误](remote-desktop-wgc-native-allocation-2026-10-18.json)。

## 支持查询与身份对照

第二轮候选 `09bf607dddbac8b4b2cd79aff0f1ba50f040b87f187f0c101d2345754601b9a9`
在同一正式窗口场景返回：
`WGC fallback capture initialization: WGC support query: bad allocation`。
失败发生在帧池、旋转与编码取帧之前。

随后用 [只读激活探针](../experiments/remote-desktop/windows_wgc_identity_check.cpp)
在 90 的同一会话 2、同一 Default 桌面分别创建独立进程：

| 进程身份 | 线程模拟用户 | WGC 激活工厂 | IsSupported |
| --- | --- | --- | --- |
| SYSTEM | 否 | 成功 | `0x8007000e` |
| 当前会话用户 | 否 | 成功 | 成功，支持 |
| SYSTEM | 是 | 成功 | `0x8007000e` |

这些结果确认该机器的 WGC 支持查询依赖进程身份，线程模拟不足以修复。
探针不采集画面、不发送输入、不修改服务或显示布局。每个子进程限时等待，
结束后回收。正式窗口 fixture 仍为零输入，原服务与布局恢复，临时任务和目录清理。
结构化证据：[身份对照](remote-desktop-wgc-system-identity-2026-10-18.json)。

微软说明 [E_OUTOFMEMORY 会转换成 std::bad_alloc](https://learn.microsoft.com/en-us/uwp/cpp-ref-for-winrt/error-handling/throw-hresult)；
该说明解释异常形式，具体身份差异由本次实机对照证明。

修复候选让 SYSTEM Default helper 的 capture/cursor 子进程使用同会话用户
身份；直接继承已有媒体管道，使用私有 kill-on-close job 约束子进程生命周期。
输入恢复与 Winlogon 采集仍由 SYSTEM 处理。候选已通过 29 项媒体测试，
完整构建通过；后续正式窗口结果见下节。独立光标及异常回收尚未验收，
不能把这一轮记为整个多屏任务关闭。

## 用户采集候选的正式窗口回归

候选 Desktop SHA256：`6f07fed21ad2bc7d706c6d21985759e162dd6f4537d36ccc529c3154c54537f9`。

- 负坐标 `(-1080, 0)`、1080×1920、90° 竖屏正常出图；两个观看窗口尺寸的四象限颜色均正确。
- 两种尺寸共 8 次点击均只在竖屏产生一次按下/抬起，最大误差 2 个远端像素；主屏零误点击。
- 按住 Ctrl 切回主屏后，Ctrl 与鼠标均释放，新 generation 默认只查看。
- 锁屏后显示系统登录页面，通过产品 SAS 与输入恢复普通桌面。登录脚本在 Enter 抬键时发现旧 generation 结束，返回失败；没有重放密码。实际恢复由画面、desktop_user 上下文、只查看状态及释放记录交叉确认。
- 普通关闭观看窗口回收采集进程；两轮显示布局恢复返回 0，临时屏删除返回 0，原服务恢复且无残留测试进程。

第一轮缩小窗口点击偏差 4 像素，定位为测试注入器使用浮点 viewport，
修正为实际整数像素边界后通过；产品坐标映射与 3 像素阈值均未调整。
另一次截图受到本机其他置顶窗口遮挡，保留失败记录后改为只采集所属原生窗口。

**独立光标仍失败**：排除遮挡后，远端 GetCursorInfo 的可见标记、形状和坐标均正常，
但观看端光标区域 4 次采样没有像素变化。正在对采集、IPC、观看端补充失败原因记录，
不将“可以移动鼠标”当作“显示光标”通过。

结构化记录：[首轮与锁屏恢复](remote-desktop-user-capture-2026-10-18.json)、
[窗口采样与八点点击](remote-desktop-user-capture-window-2026-10-18.json)。
普通非管理员用户、异常终止时的子进程回收和长时间稳定性仍需验证。
