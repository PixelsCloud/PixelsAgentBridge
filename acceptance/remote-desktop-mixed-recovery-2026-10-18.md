# Linux 混合业务中的自动重连诊断

2026-10-18，基线 `399378e`。本轮从零重跑 30 分钟混合测试，完成 19 轮后因
视频 session 改变失败，尚未通过长期稳定性。证据见
[机器记录](remote-desktop-mixed-recovery-2026-10-18.json)。

## 已确认的结果

- Windows 正式独立窗口观看 Linux Wayland 1920×1080、15 FPS 配置；19 轮
  实际显示采样 **14.25～14.71 FPS，平均 14.54 FPS**，没有无效采样点。
  这是每轮 10 秒的显示采样，不能当作全程逐帧测量。
- 每轮 4 MiB 上传、远端哈希命令、同一 PTY 标记、下载与哈希校验均通过。
- 第 19 轮后、约 9 分半钟处自动进入 reconnecting，随后新 session 获得首帧，
  从重连事件到首帧约 **0.94 秒**；前后均为只查看、D3D11 硬件解码。
  这次已能确认具体失败条件，不再沿用上一轮缺失状态的组合断言推测。
- 观看期间另一个独立 Bridge 观看者连接被明确拒绝为 Busy；原 session 与
  只查看状态不变。该探针未启用操作或发送输入，退出状态已收集。
- 原服务、活动会话和 1694×1102 显示模式恢复，自有进程、输入设备、测试目录
  和上传文件清理；本机私有 Desktop 与 GPU 观察进程正常退出。

## 排查范围

本机事件时间为 09:25:04.752 UTC。Linux Executor 文件日志在远端
09:25:24.873 UTC 记录 `remote desktop MediaUnavailable: local WebSocket closed`。
事后三次时钟往返测量的最窄偏差界限约为 **+20.146～+20.254 秒**；在期间没有
时钟跳变的假设下，两者时间相符。不能直接减去未校准的跨机时间戳。
上一轮远端也有本地 WebSocket 异常关闭记录；这只能缩小范围，尚不能确定
helper 主动退出、会话校验变化或其他通道关闭条件谁先发生。

当时系统会话仍活动且未锁屏、动画继续运行，回滚计时器未触发。19 轮内采集
worker PID、234708 KiB RSS、34 个 fd 和 11 个线程保持一致；这些短期样本
不证明长期无泄漏。GPU 观察只有末段三次，不做稳定平台期结论。

## 诊断改动

测试 WebView 订阅已有状态事件，去重后保留最近 256 条及丢弃计数，并在失败前
保存快照。会话变化与输入启用分别断言，避免再次只留下空 AssertionError。
产品自动恢复前向现有轮转日志记录错误、renderer/recoverable 分类和窗口标识；
不改变恢复策略、身份核验或可靠传输，不记录输入正文。

JavaScript/Python 语法检查、Rust 格式检查及完整 Windows Desktop 构建通过；
新二进制哈希单独记录，尚未做新日志的实机故障验证。构建 3 jobs、嵌套构建 1 job；
其他项目新启动 8 jobs 时曾短暂合计 11，发现后暂停自有构建，并增加持续监测。
不能声称整个构建期间总并发始终不超过 10。

本轮不关闭 W7 / LT-06.7，不执行 COS 发布。下一步保留 Linux helper 的退出
原因和本地媒体通道日志，定位触发条件后再从零完成持续测试。
