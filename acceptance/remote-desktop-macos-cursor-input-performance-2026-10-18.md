# Apple 正式窗口光标、输入及性能回归

日期：2026-10-18，基线 `8526acb`。方向为 Windows 操作端 → Apple 单屏。
继续使用上轮的隔离 Windows Desktop、已授权固定 Mac App 与新版 Executor；
本轮没有编译或覆盖安装版。原始脱敏数据见 [JSON](remote-desktop-macos-cursor-input-performance-2026-10-18.json)。

## 光标与输入通过的范围

通过正式协助弹窗打开独立窗口，默认只查看，实际 D3D11 硬解。正式 helper
分别启动视频、光标进程；关闭窗口后两者退出，协助状态返回 waiting。

自有白色测试窗口内，依次验证箭头、自定义光标、隐藏、显示、移动、移回、恢复
箭头。读取的是 Windows 合成后的窗口截图，而非原生 worker 的协议输出。
原生 9×7 自定义图像在当前缩放下占 8×6 个显示像素；远端移动 20 个逻辑像素，
显示位置移动 17 像素。隐藏时整个所选白色客户区为白色，没有遗留光标；移回和
恢复后的光标像素与初始形状完全一致。这证明所选区域的形状/位置/可见性，不替代
全视频逐像素检查、其他缩放比例或多屏验收。

新增 [截图分析工具](../experiments/remote-desktop/analyze_macos_cursor_product.py)。
初版要求整个区域逐字节相同，因左下边缘一个背景像素的蓝通道差 1 而失败；
定位后对光标包围盒保持精确相等，视频背景使用既有 5 级差异阈值并记录最大偏差。
本轮光标恢复最大背景偏差为 0/1/0。以实际截图替换构造的缺失、未隐藏、未移动
三个负例均被拒绝；未通过降低光标像素精度掩盖差异。

随后在另一个自有输入窗口点击“启用操作”，向本机拥有的原生 viewer surface
投递鼠标/键盘消息，经产品链路在 Mac AppKit 窗口观察事件：

- 一次点击仅收到一对按下/释放，期望客户区 `(100,100)`，实际 `(99,101)`。
- A 键收到一对按下/释放，Mac keyCode 为 0；滚轮收到一次事件。
- 按住 Shift 后关闭远程窗口，AppKit 收到一次释放，shifted=false。
- 后续系统只读检查中，combined session/HID 两种状态的左右 Shift 均未按下。

没有向其他应用发送输入；本轮不覆盖双击、拖拽、输入法或完整组合键矩阵。

## 性能没有通过，必须继续定位

使用已校验源码/二进制哈希的自有 1920×1080、30 FPS 动画，viewer 选择 15 FPS。
采样器从实际桌面合成画面的两行互补编码读取帧 ID，按完整测量时间计算，
不以网络包数、解码提交数或丢弃停顿尾段计算通过。

| 轮次 | 实测 | 判定 |
| --- | --- | --- |
| 正式窗口第一轮，30 秒 | 1797 次采样全无效，未识别帧 ID | 观察无效，不能解释为视频 0 FPS；原因未确定 |
| 正式窗口第二轮，30 秒 | 1787 次采样、0 无效，稳态 **6.776 FPS**；最长间隔 **1.800 秒** | 有效失败，低于 >12 FPS 要求 |
| 独立原生显示诊断 | 90 帧确认显示，扣除预热后 **11.75 FPS** | 失败；首代次未达阈值，未执行第二代次 |

第二轮每五秒实际不同帧数为 74、73、46、6、11、18，体现后半段明显降速。
原生对照的 74 个采集时间间隔合计 6,115,221µs，接收跨度 6,149.68ms，
显示收尾 115.11ms，并行环境查询最大 32.22ms。这个对照没有正式 UI 和独立
光标订阅，且测量时间不同，不能直接将两者差值归因于 UI 或光标。

给 [采样器](../experiments/remote-desktop/windows_sample_presentation.py) 增加表面
屏幕坐标、采样点及首个无效样本颜色/位值诊断；第二轮没有无效样本。
尚未修改产品采集或反馈逻辑。下一步优先对照 ScreenCaptureKit 原始回调节奏、
编码耗时、发送额度等待/恢复和原生显示确认，确定降速来源后做修复与同条件回归。
源码中的 `minimumFrameInterval=1/fps` 与双层节奏控制只是调查线索，不能当作已证实根因。

测试窗口目录已清理。Windows 隔离进程和原生诊断进程均已退出。

以 `blocked by policy` 拒绝，本轮没有重试或绕过，仍由当前用户/SYSTEM ACL 保护、
