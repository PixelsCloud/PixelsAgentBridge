# Mac 与 Linux X11 动态布局边界

日期：2026-10-20。源码基线 `5f65459` 加本批 Mac 修复；[原始结果与产物哈希](remote-desktop-macos-linux-layout-boundary-2026-10-20.json)。本批只补缺项，没有重跑已通过的 Windows 动态 DPI、多屏、光标及三平台登录验收。

## 修复与结果

Mac 原先只检查屏幕在线状态和逻辑 bounds。同一逻辑尺寸切换像素密度时，ScreenCaptureKit 仍可能交付原配置尺寸，旧布局因而被继续接受。现在同时检查当前模式的像素密度、像素尺寸；采集等待帧额度时也检查布局，编码完成后再核对一次，拒绝输出旧布局的视频包。在线但 inactive 的锁屏/熄屏显示器仍被接受。

原生回归在修复前以退出码 2 报出同 bounds 密度漏检；修复后六项通过，包含在线 inactive、主屏 ID、断开、几何变化、同 bounds 密度变化、模式缺失。Mac release 构建使用 4 个作业、嵌套构建 1 个作业；固定测试 App 路径与签名身份不变。

| 范围 | 本批实测 | 结论边界 |
| --- | --- | --- |
| Windows 正式观看窗口→Apple | 1920×1080→1280×720→1920×1080；按住 Ctrl 时切换，目标系统键状态释放；新配置先到、首帧前输入暂停，恢复后只查看 | 两次切换均自动建立新的 session/generation 二元标识；不是要求 generation 数字跨 session 递增 |
| Apple 真实点击 | 原尺寸 `(100,100)`，小尺寸 `(99,101)`，恢复 `(100,100)`；每次只收到一对 down/up | 源端使用实际原生显示区、目标为自有聚焦夹具；最大误差 1 像素 |
| Mac 无帧额度布局变化 | 先取得实际编码帧，再停止给予额度；真实变更显示模式后约 664 ms 观察到采集退出，错误为 `Screen changed; refresh generation`，额外输出 0 字节 | LaunchServices 启动器返回 0 不代表 worker 返回 0；实际 worker 退出码不可观察，只记退出事实 |
| Linux X11 正式原生 worker | 1306×768→1280×720；按住 Ctrl+左键，约 256 ms 旧输入 worker 退出，系统状态及夹具均确认释放；旧几何重建被拒绝 | 使用生产 worker 的真实 IPC 和真实 XRandR 变更；不是完整 Desktop 窗口恢复测试，也不是 Wayland 结果 |
| Linux 旧采集与新布局 | 无额度时旧采集仍存活；下一次拉取退出且没有旧包。新输入点击 `(170,144)` 精确匹配，新采集首帧 IDR、index 0 | 不把“下一次拉取拒绝”写成“无额度主动退出”；既有输入通道独立退代，无需新增 Linux 修改 |

Mac 实机只有单屏 1x；同 bounds 2x 密度变化来自确定性原生回归，不冒充真实 Retina 切换。Windows 操作端复用 `e61ab5dd…`，Mac 修复后签名产物为 `d382b0e5…`；Linux worker 为 `d6f0117e…`，完整哈希见 JSON。

## 测试前提与恢复

Apple 自动锁屏曾导致自有夹具未获焦点，驱动在前提断言处停止，没有把点击发到无关窗口。恢复解锁后只继续尚未通过的步骤。直接从 Python 启动原生采集因负责进程没有屏幕录制授权而失败；改为通过 LaunchServices 启动原有已授权 App 后成功，没有重新申请权限。上述准备失败保留在私有原始记录中，不算产品用例通过。

Apple 精确恢复模式 34（1920×1080），Ctrl 已释放；临时服务、helper 和夹具退出，原服务恢复且安装文件哈希不变。Linux 恢复 1306×768、Ctrl/左键均释放，自有 worker 退出，原安装服务仍 active。Windows 隔离 Desktop 退出，自有凭据槽撤销、原槽未变。私有凭据副本及诊断文件继续受限保留，没有重试此前被拒绝的删除。

未替换本机安装版，未 push、打正式安装包或发布 COS。
