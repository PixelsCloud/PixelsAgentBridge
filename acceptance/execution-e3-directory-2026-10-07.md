# E3 指定用户目录分页

## 实现范围

- `pab_list_directory` 增加与命令/文件相同的 `execution`。缺省 service 继续原目录入口；user 使用本连接发现的 context_ref，要求 filesystem v6，旧端不会忽略选择而以服务身份执行。
- 复用 FileSystemAction、FileEngine、原生 user-worker、接受事务、指纹与持久化。没有第二套目录工作进程或数据库。
- 用户进程执行目录枚举；页结果及历史保存实际执行身份。Bridge 核对请求 ID、路径、排序、游标、数量和身份一致性；本地记录保留条目数，进行中的目录请求纳入断开前活动检查。
- 分页仍是名称游标，最多 64 项、扫描最多 20,000 项。目录变化时它不是快照；调用者每页明确使用同一用户选择。无权限目录失败，不以 root/SYSTEM 重读。
- 转义后超出回复预算的目录页返回 `directory_page_too_large`，清除大页内容并建议减小 limit；测试证明缩到单项后能继续读取。

## 验证

原生集成测试扩展现有 `native_user_filesystem_worker_acceptance`，目录请求经过真实 QUIC 和正式文件执行入口。复制出两个文件后按每页一项读取英文/中文名字，核对游标与结束、实际身份及历史；另验证服务私有目录不可读。原有写入归属、权限、路径锁、重连查重和恢复测试一并执行。

| 平台 | 证据 |
|---|---|
| Windows90 SYSTEM → WTS1 Administrator、WTS2 普通用户 | 最终源码两用户通过；任务 `99a0d19e-25e3-4df9-9fc6-8e5998f950f6`，两轮分别退出 0，末尾检查无目录/工作进程残留 |
| macOS root → UID501 | 最终源码任务 `93331297-008d-43a0-bda7-217eede3cc52` 退出 0，目录回归 7 项及原生集成通过 |
| Linux 无 GUI/logind 容器 root → UID23001 | 最终源码目录回归 7 项、原生集成通过；受控容器退出 0 |

本地回归：Executor 文件测试 51 项、目录测试 6 项、MCP 36 项、Bridge 文件测试 8 项、目录响应测试 1 项、文件协议版本测试 1 项通过；workspace tests 编译检查通过。
Mac/Linux 额外运行控制字符文件名的页大小测试，Windows 文件系统不允许这些文件名。

测试中发现整套异步工作流随用例增加发生默认线程栈溢出；修复为单次测试操作返回 boxed Future，三平台在默认线程栈下通过，未提高线程栈参数，也未修改产品线程栈。

清理最终证据：Windows 上述验收任务、Mac `47c49f0b-97c1-45c8-b96f-fbade5e81716` 均为 0 个测试目录、0 个工作进程；Linux 容器自动删除。
