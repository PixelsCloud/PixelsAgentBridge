# Mac/Linux 操作端剩余登录组合验收

日期：2026-10-20。基于 `321a1ca` 的生命周期错误回复修复，本批补齐上批明确留下的三个组合，未新增产品代码。结构化结果、产物哈希、私有原始记录和截图哈希见[证据清单](remote-desktop-posix-operator-login-2026-10-20.json)。截图含实际桌面和设备信息，仅在受限本地目录保留，未发布图片内容。

## 本批结果

| 操作端 → 被控端 | 实际流程和结论 |
| --- | --- |
| Mac → Linux | Apple 正式独立窗口、硬件解码。Linux 从 X11 用户会话 22 注销到 Wayland GDM c3；原窗口自动恢复登录画面，只查看。明确启用操作，选择 hy，实体键经 Mac 产品窗口提交一次密码；进入 Wayland 用户会话 611。原窗口自动恢复桌面并重新只查看，无手动重开、无密码重放。窗口 PID 85733、原生窗口 ID 794、产品 viewer ID 全程沿用。 |
| Linux Wayland → Mac | 会话 611 使用 `GDK_BACKEND=wayland` 的正式窗口，软件解码 Apple 1920×1080。通过窗口点击 Apple 菜单锁屏，锁屏画面和密码框可见；实体输入经 Linux uinput → Linux 产品窗口 → Mac，单次密码后原窗口返回桌面。本例媒体会话未退代，操作保持启用；结束前明确停止操作并关闭窗口，不把它写成“退代恢复只查看”。 |
| Linux Wayland → Windows 90 | 同一 Linux 原生操作端 PID 98661。90 锁屏后，从产品工具栏发送 Ctrl+Alt+Delete；安全桌面交接恢复只查看，再明确启用。实体输入经 Linux uinput → Linux 产品窗口 → 90，单次密码解锁 Administrator 会话 2；原窗口自动恢复桌面和只查看，无手动重开和输入重放。 |

三例的目标登录输入均经过对应产品窗口。Windows 上的既有原生输入驱动仅给操作端机器发送实体输入，用来替代测试人员的键盘；未绕过窗口直接给目标提交登录密码。Wayland 操作端未用 XTest 冒充有效输入路径。

原 Mac→90、Linux X11→90 的[上批通过结果](remote-desktop-operator-windows-login-recovery-2026-10-20.md)，以及 Windows 操作端、三平台被控端已有登录/注销/开机记录直接复用，未重跑。2 小时和 8 小时仍按用户要求暂缓。

## 构建与异常观察

Linux/macOS 的缓存源码先验证为上批修复前基线，仅更新共享 `crates/remote-desktop/src/lib.rs` 的错误分类；分别编译固定后的 Executor。每台机器最多 10 个 Cargo 作业，嵌套构建限 1，同机未并行启动另一个编译。Windows 复用上批固定 Executor `bcf01684…`，Mac GUI `c7a59763…`、Linux GUI `3abb4459…` 沿用已验收产物，无 GUI 重编译。

Linux GDM/用户会话刚启动时，Mutter 尚未注册，原窗口出现可恢复的 `MediaUnavailable`，随后自动恢复；未修改重试策略或延长产品恢复时限。Mac→Linux 准备阶段一次控制服务短暂不可用发生在密码提交之前；先只读核对状态后继续，没有重放不确定输入。

隔离 Desktop 的可选 MCP 报告监听端口被已安装 App 占用，留下 `Address already in use`；测试使用独立 MCP 连接，实际画面及输入有效，未为消除这条日志停止其他会话的已安装 App。

保留其他准备失败：旧 macOS `CGSession` 工具不存在，前置检查在提交标记之前退出，改用产品窗口的 Apple 菜单；Windows 暂存产物路径改写的本地断言失败发生在远端部署之前。环境恢复时，未经过 supervisor 的独立 GDM 截图因缺 DMA 通道失败；另一次本地原生窗口截图未得到期望画面，不计验收证据。首次限时恢复夹具到期前未提交密码；新恢复夹具单次登录 X11 后在会话交接处以 EOF/exit 1 退出，这个诊断驱动没有产品窗口恢复循环。最终系统状态另行确认，未把该退出码改写为成功。

这些准备/恢复记录均不替代三个正式产品窗口的通过结果。未改变密码、自动登录、权限授予或产品鉴权。
