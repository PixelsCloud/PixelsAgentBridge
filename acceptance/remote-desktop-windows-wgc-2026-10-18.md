# Windows 竖屏 GPU 后备采集与正式窗口剩余问题

日期：2026-10-18。目标：90，临时 Parsec 竖屏 (-1080,0)、1080×1920、100% DPI。
本轮不关闭长期清单条目；仍为 10/53 完整关闭。结构化证据见
[同名 JSON](remote-desktop-windows-wgc-2026-10-18.json)。

## 已验证

- 同一自有四象限窗口，GDI 四点颜色正确；DXGI 四次重新创建 duplication，
  每次首帧 LastPresentTime=0、四点全黑，第二次取帧均为 0x887a0026。
  因此不能把零时间戳首帧直接交给编码器，简单重建也没有恢复本机此输出。
- 原始 WGC 采集同一屏幕，取得已旋转的 1080×1920 GPU 纹理，四点 RGB 完全匹配。
- 新生产适配器把 WGC 纹理在 GPU 逆旋转为协议既有的 1920×1080 原生方向。
  独立测试先拒绝过期尺寸，再用正确尺寸启动；四点顺序为绿、黄、红、蓝，颜色完全匹配。
  测试程序才执行四点回读，生产路径没有像素 Map。
- 实际媒体 worker 在该输出自动经历 DXGI ACCESS_LOST → WGC → NVENC，连续输出
  45 个顺序正确的 H.264 包，首帧 IDR、正常退出。自有小动画窗口的约三秒短测，
  排除首帧后采集编码约 15.05 FPS；两条运行日志确认 GPU 采集和 NVENC、零 CPU 回读。
  这是原生采集编码速率，不能冒充端到端显示 FPS 或长期性能。
- 新完整 Desktop 内嵌媒体程序在普通用户上下文也能返回竖屏编码首帧，正常退出。
- 媒体 worker、完整 Desktop 构建及 23 项媒体单测通过。Cargo 最多 3 jobs，
  单独 C++ 诊断固定 1 核；本轮无超过 10 核的编译。未更新本机安装版。

## 实现边界

原有 DXGI 正常输出路径保留；仅取帧 ACCESS_LOST 后尝试 WGC，并检查仍是相同的
普通输入桌面、屏幕 ID、HMONITOR、坐标、尺寸和旋转。锁屏或拓扑变化继续使代次失效。
WGC 使用两帧池、有界等待与最新可用帧消费；帧租约保留到编码结束。
无旋转时直接交付 GPU 纹理，有旋转时执行一次 GPU 视频处理。WinRT 使用单独 C++20
编译单元，其他 Windows 原生代码仍为 C++17。WinRT 运行环境在共享 D3D 设备释放后退出。

## 正式窗口仍未通过

新正式 Desktop 的主屏能进入 viewing，实际 D3D11 硬解、默认只查看。
切换负坐标竖屏后反复 reconnecting，未进入允许输入的状态，本轮没有发送鼠标键盘。
独立运行同一 Desktop 的 cursor worker，已输出 6449 字节后退出 1，错误为
`Cursor AcquireNextFrame HRESULT=0x887a0026`。视频单独出图和光标失败的证据分别保留；
没有仅凭日志断言正式窗口重连的全部原因已经查清。

下一步须协调 WGC 视频与独立光标的来源，避免隐藏真实光标、重复绘制或使用过期位置；
随后重测正式窗口四象限、缩放后点击、按住修饰键切屏、屏幕移除与锁屏恢复。
混合 DPI、其他旋转角度、全平台矩阵、长期稳定性和 COS 发布仍未完成。

## 保留的失败与修正

- 第一轮 DXGI 诊断上传前未建立远端目录，后续启动引用不存在任务；没有成功启动屏幕租约。
  修正为先建立专用目录和检查旧任务后才继续，原错误保留。
- 初版适配器在拒绝过期尺寸后立即结束 WinRT 运行环境，再次初始化时访问异常。
  带阶段日志的第二轮复现同一边界。改为让运行环境覆盖共享 GPU 设备的完整生命周期，
  后续负向检查和正常初始化均通过；未采集崩溃转储，不推断具体驱动内部调用栈。
- 一轮未确认自有四象限画面即安全退出；加入最多五秒的相同像素前置条件等待，
  没有放宽颜色阈值或绕过画面确认。
- 原生编码测试的 PowerShell 5.1 驱动把 JSON 数组包成嵌套数组，错误拼接多个屏幕 ID，
  导致 Selected screen disappeared。首次驱动也未保留子进程 stderr，均不算产品通过。
  修正数组展开与错误收集后成功；另一次晚到复测因限时屏幕已移除而拒绝运行。

## 资源恢复

每轮临时显示器均由限时租约移除，原主屏恢复；诊断阶段原服务路径和 PID 25632 未变。
正式窗口阶段使用独立候选服务和七分钟看护、独立恢复任务，结束恢复原服务，
输入释放记录为零。本机隔离 Desktop 已退出，私有凭据目录保留在 Git 忽略目录。
远端日志下载后与源文件 SHA-256 对照，专用进程、任务和目录按归属清理。

实现参考 Microsoft 的 [WGC 无 DispatcherQueue 帧池](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.direct3d11captureframepool.createfreethreaded)
与 [COM 退出时序](https://learn.microsoft.com/en-us/windows/win32/api/combaseapi/nf-combaseapi-couninitialize)。
此前同时检查了本地 RustDesk 的 DXGI 零时间戳处理和后备采集逻辑，未复制其实现。
