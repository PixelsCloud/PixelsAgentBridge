# Windows 原生媒体与可靠流接入验收

日期：2026-10-16。范围：独立实验程序；未更新安装版。

## 已完成

真实 DXGI / GPU 合成图 → NVENC 直接纹理输入 → 压缩码流管道 →
`DesktopHost` → 项目 QUIC 可靠分帧 → `RemoteDesktopSession` →
压缩码流管道 → D3D11 硬解 → 原生 swapchain → DXGI 逐帧显示确认。

与上一阶段确定性字节测试不同，本轮实际编码、传输、解码并显示 H.264。
本机与 90 分别在各自机器上运行这条闭环，不能作为本机已收到 90 画面的证据。

每次测试包含两代视频流，第二代通过重新选择当前屏幕 ID 触发；每代预热一秒
目标帧数，再测量五秒目标帧数。窗口固定为 960×540，流分辨率使用实际屏幕尺寸。

| 机器 / 场景 | 流分辨率 | 目标 FPS | 第一代显示 FPS | 第二代显示 FPS |
| --- | --- | ---: | ---: | ---: |
| 本机 RTX 3060 / 合成图颜色校验 | 3840×2160 | 15 | 14.999 | 14.997 |
| 本机 RTX 3060 / 合成图 | 3840×2160 | 30 | 29.994 | 30.001 |
| 本机 RTX 3060 / DXGI 桌面 + 动画窗口 | 3840×2160 | 15 | 14.999 | 14.996 |
| 本机 RTX 3060 / DXGI 桌面 + 动画窗口 | 3840×2160 | 30 | 30.000 | 30.005 |
| 90 RTX 4090 / 合成图颜色校验 | 1920×1080 | 15 | 15.002 | 14.997 |
| 90 RTX 4090 / DXGI 桌面 + 动画窗口 | 1920×1080 | 30 | 29.997 | 29.999 |

本机数据取最终回归；首轮数据也保存在 JSON 中。90 的运行版本早于最后追加的
父进程 EOF 检查和客户端 offer 读取线程清理；这两项退出路径在本机补验。
本机当时为 4K、150% 缩放，90 为 1080p，均未改变显示设置。

合成画面颜色最大误差分别为 3/255 和 2/255。性能场景没有测试像素回读；编码
输入没有显式像素 CPU 回读或中间 GPU 纹理复制，解码输出经过一次 GPU 颜色转换
写入 swapchain。驱动内部复制未知，压缩字节的 CPU 传递不属于纹理零复制承诺。

同连接上每秒执行一个旧 `GetPresence` 协议探针，首轮本机最大 1.762 ms，90
最大 0.800 ms。该探针使用实验 handler，不等于完整命令/终端/文件传输的带宽
竞争验收。接收后解码/显示 P95 不包含远端采集及网络耗时。

## 生命周期与回归

- 每代从新的解码初始化关键帧开始；backend permit 保证旧采集子进程退出前，
  新 generation 不会启动第二个采集源。
- 关闭本测试创建的查看窗口，Rust 会话退出，采集与显示子进程结束。
- 强制终止本测试创建的父进程，媒体子进程通过管道断开退出，没有遗留窗口。
- `cargo test -p pab-remote-desktop`：3 项会话单元测试、6 项真实 QUIC 测试通过。
- 原生程序使用 `/W4 /WX` 编译通过，没有新增应用配置文件。

编译使用最多 10 核亲和性；Rust 为 4 jobs，MSVC 为 1 job，顺序运行。同机另一
构建的 Cargo/native 预算确认为 3/3 后才合并计算并启动，没有停止其任务。

## 跨机器尝试与清理

通过现有 MCP 已认证通道上传临时二进制，在 90 的现有 Administrator 用户上下文
启动独立端点；没有新建设备、账号或更改已安装服务。独立端点只给出了
`10.0.0.90` 内网地址，本机连接超时，未建立跨机器视频会话。

代码检查确认现有 Relay 需要控制服务授权，临时探针密钥没有这种授权。本轮
没有服务端日志来唯一定位超时原因，没有放宽线上准入。后续应接到正式
Executor / 交互桌面 helper，复用正常设备连接授权。

首次清理因远端探针仍在等待而无法删除使用中的 exe。探针按 80 秒截止退出后，
完成上述 90 本地回归，最后删除两个指定临时 exe 及空目录，清理退出码为 0。
未锁屏、重启、注入输入或更新本机/90 的安装版。
