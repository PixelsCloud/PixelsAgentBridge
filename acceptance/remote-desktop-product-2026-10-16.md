# 正式 helper 媒体与已认证跨机器画面

日期：2026-10-16。分支：`feat/remote-desktop-v1`。
本记录是开发验收，不表示三平台远程桌面首版完成，不发布安装包。

## 接入范围

- 新增 `crates/desktop-media`，正式构建直接编译 Windows 原生源文件。
  采集 DXGI BGRA 纹理直接交给 NVENC，压缩 H.264 经现有可靠流传输，
  操作端 Media Foundation D3D11 解码，GPU 视频处理器缩放/旋转并显示。
  产品没有全帧 CPU 回读；四像素回读仅在显式合成校验模式使用。
- Executor 注册 `HelperMediaBackend`，通过已有本地 HMAC 和内核进程身份核验
  建立独立媒体 helper socket。媒体使用有界二进制分块；不进入原截图/窗口队列。
- Desktop 增加独立窗口入口、默认只查看、稳定 ID 屏幕选择、15/30 FPS、全屏和
  重连。视频在原生子窗口显示，WebView 只接收状态与屏幕元数据。
- 静态桌面等待新帧不超时；已开始但未完整传输的帧仍有超时。切屏先终止旧源，
  再枚举屏幕并建立新 generation，避免静态采集占住 helper 造成切屏死锁。

## 90 到本机的真实连接

目标：Windows Server 2022，RTX 4090，Administrator Session 2，1920×1080。
操作端：Windows，RTX 3060，本地 3840×2160 显示器。
码率配置：H.264 6 Mbps，无 B 帧/前瞻；网络未做限速或 RTT 注入。

通过 `pab-bridge` 的 `remote_desktop_check` 示例运行正式 BridgeRuntime。
使用当前账号、已保存设备密码和新建临时操作端密钥；没有复制安装版端点私钥，
没有另建被控设备身份、媒体鉴权或媒体中继。目标桌面中的有时限动画窗口用于
提供动态内容；视频不落盘。

| 首轮路径 | 档位 | 实际有效显示 | 确认显示帧 | 结果 |
| --- | --- | --- | --- | --- |
| `Direct` | 15 FPS | 15.0494 FPS | 90（15 预热 + 75 测量） | 通过 |
| 强制 `Relay` | 15 FPS | 15.1000 FPS | 90 | 通过 |
| `Direct`，旧同步显示统计实现 | 30 FPS | 19.9565 FPS | 180 | 未通过 30 FPS 档位验收 |

前两项在关闭画面后又执行了正常环境查询，连接仍可用。首轮只覆盖普通桌面；
尚不能据此认定终端/文件并行、多屏、锁屏或登录恢复通过。

第二轮使用异步显示统计、结束时排空统计的计时器；每轮 30 帧预热、150 帧测量。
同一个查看会话以稳定屏幕 ID 重建 generation，期间每秒查询一次普通执行环境。

| 路径 | generation 1 / 2 实际显示 FPS | 两轮显示计数 | 普通查询最大耗时 |
| --- | --- | --- | --- |
| `Direct`，30 FPS 档 | 29.2105 / 29.4454 | 各 180 / 180 | 30.13 ms |
| 强制 `Relay`，30 FPS 档 | 27.7339 / 28.4443 | 各 180 / 180 | 424.89 ms |

两条路径均验证重复打开返回 Busy、同屏重建成功、关闭后普通连接继续使用。
这是同屏重建，不是真实双屏验收。例程按确认显示数扣除全部预热提交数，保守
计算 FPS；未确认的 present 单独报告。一次 Relay 中间试验仅确认 179/180 帧，
保留此事实；表内为后续完整复测，不将中间未确认帧算作已显示。

目标端测试使用随机独立临时目录中的 Executor 和 media-only helper，临时停原
Executor 服务，保留其服务配置、安装文件、设备数据库和身份。预先注册 SYSTEM

两轮结束均确认原服务 Running、无测试进程；临时文件与四个计划任务均已删除。
本机安装版没有更新。

## 显示调度修复与本地原生验收

普通合成窗口的显示统计可晚于提交多个刷新周期。旧实现逐帧等待统计再允许
下一帧解码，造成 30 FPS 档实际约 20 FPS。改为最多三个待确认 present ID，
持续观察统计；只有明确观察到的 ID 才计入显示帧数。跳过的 ID、旧帧重绘、
最小化消费都不冒充新显示帧；结束时排空统计。

此处按 [Microsoft 的 flip-model 统计说明](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/dxgi-flip-model)
区分提交 ID 与实际显示统计。IPC ACK 表示解码/渲染消费；显示计数单独返回。

本机 4K 生产 worker 经可靠 QUIC，每项连续两个 generation：

| 内容 | 档位 | 两轮有效显示 FPS |
| --- | --- | --- |
| 合成颜色校验 | 15 | 15.0060 / 15.0020 |
| 合成动态画面 | 30 | 29.9943 / 29.9731 |
| DXGI 采集动态桌面 | 15 | 14.9991 / 14.9969 |
| DXGI 采集动态桌面 | 30 | 29.9698 / 29.9967 |

原始本地报告：`.build/remote-desktop/stream-media/verify-1a59ac0deb23/report.json`。
该轮沿用旧实验计时器，计时结束点在统计排空之前；后续验收示例已修正为排空后
计时，并将原 `receive_to_display_p95_ms` 更名为 `receive_to_renderer_consumed_p95_ms`，
避免将消费确认时延描述成显示时延。新指标需在后续构建中复验。

`verify_native_parent.py` 使用独立原生父窗口与合成视频，四方向均通过：
嵌入、72 逻辑像素工具栏留白、宽高比、静态缩放、最小化/恢复、退出；
每方向 26 帧解码，21 帧确认显示，RGB 最大误差 3–4，最小化帧不计显示。
测试自身的管道读写均在线程中执行，父窗口线程持续处理 Windows 消息。
突发父进程退出测试已确认采集和显示子进程退出。

## 后续输入协议基础（尚未接入原生输入）

桌面协议升级为 v2，增加输入能力标记、显式启用/禁用、带 generation 的输入事件。
每次切屏重置为只查看，旧代次的控制句柄不能输入或禁用新代次。坐标映射使用选中
屏幕的桌面矩形，保留负原点；已旋转画面不再次旋转，也不重复应用 DPI 比例。
输入的 Debug 输出隐藏事件内容。旧媒体版本需要升级，普通设备协议保持不变。

增加独立输入控制句柄，发送输入时无需取消待收视频帧；静止画面不会因此形成
“等待画面变化才能发送使画面变化的按键”的相互等待。服务端在媒体代次结束、
禁用、切屏或输入超时后丢弃输入 sink；超时不重放事件。原生 sink 的释放行为
仍须下一步接入和实测，目前不能据此声称操作系统按键释放已经通过。

验证命令（编译 8 jobs，与当时另一会话的 2 jobs 合计 10）：
`cargo test -p pab-remote-desktop -p pab-protocol -j 8`。
结果：协议单元 67、协议上下文 3、桌面单元 5、可靠会话集成 9 全部通过。
后续增加媒体失败释放用例，`cargo test -p pab-remote-desktop -j 2` 的桌面单元
5、可靠会话集成 10 全部通过，包含媒体停止时撤销输入但保留普通连接。
新增用例覆盖：旋转/缩放屏幕坐标端点、输入默认禁用、切屏/断线释放、超时中止、
旧控制句柄失效，以及等待静帧期间通过另一句柄输入后收到下一帧。

增加仅启动媒体 helper 的 `--media-supervisor` 测试入口，复用原有 Windows
Default/Winlogon 身份与启动逻辑，用于后续独立验收，不重复注册旧窗口/截图提供者。
尚未将它部署到 90，尚未执行锁屏/登录验收；原生键鼠、崩溃恢复和 UI 输入仍未完成。

同轮新增独立 helper 输入 socket，继续使用现有本地 HMAC/内核身份验证。输入注册
必须匹配采集 provider 的进程、进程生命周期标记和登录会话；输入配置必须与正在
采集的完整 generation 配置一致。输入不经过静帧 `Next` 所占用的媒体请求队列。
输入 socket 关闭不会主动终止采集；采集关闭则会撤销其配对输入。

`cargo test -p pab-executor --lib local_ipc::media -j 2` 的 3 项测试通过，使用真实
Windows 内核身份挑战、独立 socket 和模拟输入 sink，覆盖静帧期间输入、旧代次
拒绝、输入关闭/采集关闭的释放，以及原有二进制传输和取消回归。不是原生按键
验收。生产 `NativeBackend` 仍未声明输入支持，不会由本次协议/IPC 改动启用输入。

输入禁用确认当前代表撤销输入路由；不能当作 OS 已处理释放的证明。跨 helper
的释放确认与异常退出恢复仍须完成后，再进行锁屏切换中的按键残留验收。

最终定向回归：`cargo test -p pab-executor --lib media -j 8` 共 5 项通过，额外包含
进程生命周期/登录会话配对与服务账号拒绝策略。Windows Desktop debug 构建通过
（7 分钟，含媒体 supervisor 和输入 v2 会话基础）；后续 helper 输入 socket 改动
已通过上述 Executor 构建与测试，尚未重新生成用于部署的 Desktop 安装包。

后续原生输入已接通并在 90 完成点击、键盘、滚轮、停止/关闭以及输入进程崩溃后的
释放验收；最新进展和构建哈希见[原生输入验收](remote-desktop-input-2026-10-16.md)。
上文“尚未接入原生输入”描述的是此前协议/IPC 基础检查点。
