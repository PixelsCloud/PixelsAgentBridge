# Linux → Windows 正式窗口动态显示

2026-10-17，代码基线 `0614a7d`。本次验证 Linux 被控端向 Windows 操作端的
1080p 动态画面，经既有认证、可靠传输和正式独立窗口后，有效显示超过 12 FPS。
完整事件时间、帧编号、二进制哈希和远端任务编号见
[机器可读记录](remote-desktop-linux-presentation-2026-10-17.json)。

## 方法与结果

Linux VM 556688188 使用 Ubuntu 22.04.5 GNOME Wayland、2 vCPU。临时切换现有
单屏到 1920×1080，使用完整 Linux Executor 和 Desktop 注册媒体 helper。
采集为 PipeWire CPU 后备，经过必要的 I420 转换和随包软件 H.264 编码。
Windows 在 AI 协助提示中主动打开正式窗口，始终保持只查看，配置为 15 FPS。

专用 GTK 全屏画面持续改变整个画面的色块，并绘制 12 位递增帧编号、固定标记
和反码校验行。Windows 直接读取桌面合成后的原生显示区域，按实际颜色识别编号，
不以解码回调、配置帧率、重复呈现或请求次数充当有效显示。只保存生成的编号和
时间，不记录用户桌面内容。原生 surface 为 1650×1032，1080p 画面保持比例缩放
显示；本项不是 1:1 像素的全屏显示测试。

| 指标 | 实测 |
| --- | --- |
| 测量长度 | 30.001 秒 |
| 采样 | 1800 次，约 60 Hz |
| 识别到的新画面 | 408 帧 |
| 重复画面采样 | 1392 次，不计为新帧 |
| 无效校验 | 0 次 |
| 去除最初 3 秒后的有效显示 | **13.555 FPS** |
| 预热后最长无新画面间隔 | 约 105 毫秒 |

初始统计按首尾有效帧间隔得到 13.577 FPS；保存原始事件后，改为按完整 27 秒
测量窗口计算，包含可能的末尾停顿，得到上述 13.555 FPS。没有补造帧或重新
执行测试。首次采样脚本将 worker 所属子窗口误认为 Desktop 本进程窗口，未开始
采样即退出；修正为枚举隔离 Desktop 下的原生子窗口后完成上述测量。

## 恢复与边界

测试采用独立 systemd 恢复管理进程和计时器；安装目录的程序和配置未替换。
结束后已验证：原 1314×742 分辨率及布局恢复、原服务 Running、临时 drop-in
删除、原 TOML/程序/unit 哈希不变。恢复计时器停止，临时服务管理目录和 Linux
私有 profile 删除，Linux 临时 native 进程和 Windows 两个测试 profile 的进程为 0。

两份测试工具作为可复用验收脚本保存：
[Linux 动画](../experiments/remote-desktop/linux_display_fixture.py) 与
[Windows 实际显示采样](../experiments/remote-desktop/windows_sample_presentation.py)。
它们通过 Python 语法检查和此次实机运行；没有生产代码改动或新编译。

本项只覆盖当前网络与这组画面，不外推弱网、其他平台、其他桌面环境或持续运行。
Linux 系统登录、X11 产品路径、九种方向与最终候选版稳定性和发布继续待验收。
