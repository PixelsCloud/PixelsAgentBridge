## 实际通过

1. Linux MCP 使用现有认证连接 90，发起 AI 协助请求；真实主窗口显示提示并
   确认 displayed。明确点击打开后创建独立窗口，原生首帧显示后才进入 active。
2. 默认只查看。显式启用操作后，点击已聚焦的远端专用测试窗口；计数严格从
   0 到 1，远端物理位置为 (960, 540)，左键和 Ctrl 均未残留按下状态。
3. 明确点击完成协助后，Linux MCP 收到 completed/user_completed 和
   `verify_result_before_resuming=true`。AI 再通过原命令工具读取远端计数，
   确认实际点击及释放状态；此项复核由本机 MCP 执行，未宣称由 Linux 请求进程执行。
4. 独立键盘检查中，Ctrl 按下和抬起各计数一次，未残留按键。
5. 点击停止操作后，再向同一画面位置输入一次点击，远端计数不变，证明只查看
   确实停止发送输入。最后通过指定查看窗口的原生 Close 按钮关闭。

## Windows → Linux 正式窗口

后续构建完整 Linux Executor，8 Cargo jobs、嵌套 1 job，3 分 13 秒完成，产物
44,827,176 字节。通过 `/run/systemd/system` 下的单个临时 drop-in 选择测试程序，
沿用原 `/etc/pixels-agent-bridge/config.toml`。先启动独立的 systemd 恢复计时器，
再由独立管理进程执行切换；管理进程限时 7 分钟且监控测试服务退出。systemd 的
配置文件保留其强制格式，不替换项目 TOML 或安装目录中的程序。

Linux 用户的独立 Desktop 使用私有 profile，并在该目录复制同用户现有的本地
IPC 凭据，完成内核身份与活动 GNOME 会话校验、媒体/输入 helper 注册。原服务
下发的设备身份和既有密码保持不变。Windows 操作端仍使用前文已核验的测试二进制。

在同一个正式独立窗口中通过：AI 请求 → 用户主动打开 → Linux 专用全屏测试
画面首帧 → 显式启用操作 → 单击与 Ctrl 按下/抬起 → 明确完成 → AI 用原命令
通道复核 → 关闭窗口。专用窗口面积为 1314×742，点击与释放各 1 次、Ctrl
按下与抬起各 1 次；点击位置为 (656.890625, 371.28515625)，与中心
(656.5, 370.5) 的每轴误差均小于 1 像素。无 Ctrl 或鼠标残留按下。

收尾时先结束用户测试窗口与 Desktop，再请求独立管理进程恢复原服务。核实
原服务从 `/opt/pixels-agent-bridge/run-executor.sh` 启动且 Running，临时
drop-in 已删除，安装程序、原配置和原 unit 文件哈希均未改变。恢复计时器停止、
临时服务管理目录和私有用户 profile 已清理；本机测试 Desktop/WebView 进程为 0。

## 观察到的问题与修正

F24 注入没有到达远端。对照测试在同一 GNOME 会话创建独立 GTK 窗口，确认窗口
活动且绘图区获得焦点，再通过同一 Linux 输入 worker 发送 F24 和 Ctrl。结果为
F24 0/0、Ctrl 1/1，注入与释放均获后端确认。该对照未经过产品查看窗口或远程
传输，因此目前只能将缺口定位到虚拟机输入路径或 GTK 接收边界，具体根因未确认。
不把 F24 计为通过，也不据此修改产品键码映射。

运行时另发现：未保存语言偏好时，主窗口根据系统语言显示英文，远程窗口却固定
退回中文。远程窗口已改用主窗口的 `initialLanguage()`。TypeScript/Vite 构建
和现有远程桌面/协助界面 8 项测试通过；此改动发生在上述原生产物验收之后，
尚未重建并复测原生安装包，不把旧哈希的实机结果自动转给新产物。
