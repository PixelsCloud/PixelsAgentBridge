# Linux 正式操作端与 AI 协助闭环

日期：2026-10-17；运行基线 `0521a2e`。本记录证明 Linux → Windows 的一组真实
产品流程，W5/W6/W7 仍未全部完成。产物哈希和逐项结果见
[机器可读记录](remote-desktop-linux-product-2026-10-17.json)。

## 环境与方式

- 操作端：Linux 虚拟机 556 688 188，Ubuntu 22.04.5、GNOME Wayland，hy 的
  活动会话 13，1314×742、100% 缩放、2 vCPU。
- 被控端：90（428 358 431），Windows Server 2022，会话 2，1920×1080。
- 使用完整 Release Linux Desktop，以及本轮以 8 Cargo jobs、嵌套 1 job 构建的
  Linux MCP。测试时 90 使用已核验的临时 Executor/媒体 helper，限时恢复原服务。
- 既有登录和 90 的单条连接凭据只用于 0700 隔离测试目录；不修改安装版配置，
  不添加到安装版的设备列表。临时传输文件在导入后删除。
- 通过系统 AT-SPI 操作指定 PID 的真实按钮；画面使用原生 GTK/OpenGL surface，
  鼠标输入从 Linux 系统进入该 surface，再经正式可靠传输到 Windows。
  没有调用协议驱动直接跳过查看窗口。截图在本机检查，不加入仓库。

## 实际通过

1. Linux MCP 使用现有认证连接 90，发起 AI 协助请求；真实主窗口显示提示并
   确认 displayed。明确点击打开后创建独立窗口，原生首帧显示后才进入 active。
2. 默认只查看。显式启用操作后，点击已聚焦的远端专用测试窗口；计数严格从
   0 到 1，远端物理位置为 (960, 540)，左键和 Ctrl 均未残留按下状态。
3. 明确点击完成协助后，Linux MCP 收到 completed/user_completed 和
   `verify_result_before_resuming=true`。AI 再通过原命令工具读取远端计数，
   确认实际点击及释放状态；此项复核由本机 MCP 执行，未宣称由 Linux 请求进程执行。
4. 独立键盘检查中，Ctrl 按下和抬起各计数一次，未残留按键。
5. 点击停止操作后，再向同一画面位置输入一次点击，远端计数不变，证明只查看
   确实停止发送输入。最后通过指定查看窗口的原生 Close 按钮关闭。

## 观察到的问题与修正

F24 注入没有到达远端。对照测试在同一 GNOME 会话创建独立 GTK 窗口，确认窗口
活动且绘图区获得焦点，再通过同一 Linux 输入 worker 发送 F24 和 Ctrl。结果为
F24 0/0、Ctrl 1/1，注入与释放均获后端确认。该对照未经过产品查看窗口或远程
传输，因此目前只能将缺口定位到虚拟机输入路径或 GTK 接收边界，具体根因未确认。
不把 F24 计为通过，也不据此修改产品键码映射。

运行时另发现：未保存语言偏好时，主窗口根据系统语言显示英文，远程窗口却固定
退回中文。远程窗口已改用主窗口的 `initialLanguage()`。TypeScript/Vite 构建
和现有远程桌面/协助界面 8 项测试通过；此改动发生在上述原生产物验收之后，
尚未重建并复测原生安装包，不把旧哈希的实机结果自动转给新产物。
