# E3 传输接受事务、原身份恢复与 QUIC 接入

## 实现范围

- 新增 transfer v2 能力和独立 `TransferFile` 请求；参数严格解析，支持 service/user、原请求 ID 和显式 `resume_from`。旧默认传输入口保留。
- Executor 在执行前用一个 SQLite 事务写入请求指纹、完整参数、实际执行上下文及传输记录。缺少用户身份不能接受；工作程序路径在接受前解析。
- 已接受的相同请求只返回原记录，在重新连接后也不重新解析旧引用、不重新传输；同 ID 更换参数冲突，其他调用者不可读取。
- 显式续传需要新的请求 ID：上传必须保持路径、长度、哈希、覆盖设置和实际身份；下载必须引用原完整哈希、有效偏移和实际身份。原请求尚在运行或发布未确认时拒绝上传续传。
- 下载先核对预期完整哈希，源内容不符时不发送二进制内容。
- 已发布但尚未确认的用户上传，通过冻结的原生身份启动只读核对工作程序。服务能读取文件不能替代用户权限；原用户无法读取时保留未确认状态。工作程序不得通过该核对入口修改任务记录或文件。
- 接入既有 8 路文件流配额、二进制传输引擎、共享路径锁、工作进程回收和持久化完成规则，没有引入新常驻进程。

## 测试

协议测试覆盖独立 wire variant、身份字段注入拒绝、不支持的执行模式以及自引用续传拒绝。
持久化测试覆盖并发接受只有一次、缺少实际身份不落库、重复接受不改写上下文、参数/调用者隔离、数据库重开保留参数身份，且服务不核对用户发布。

原生集成改为通过真实 QUIC 的新请求驱动 TaskService，再启动目标用户工作进程：

- 二进制上传、64 KiB 后断线、显式续传、中文路径及文件所有者；空文件。
- 同 ID 在新连接查询原记录；更换 execution 拒绝且不重传。
- 续传改用 service 或改变内容拒绝且不落库；正确的上传/下载续传成功；错误下载哈希不返回数据。
- 原用户无权读写的服务私有目录、共享路径锁、错误内容不发布、初始取消。
- 模拟发布回执丢失，新连接仍用原用户核对；可读取的匹配文件确认，无权读取的匹配文件保持 committing。

macOS fixture 的大异步栈在初次运行时溢出；将多次调用的测试 future 装箱后通过，未修改线程栈大小或产品权限。
