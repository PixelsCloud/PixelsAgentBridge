# Windows → macOS：正式窗口输入与动态显示

日期：2026-10-17。基线 `5d00ede`。本轮生产二进制与上一轮首帧验证相同；
新增的是实机验收工具和记录，没有替换安装版文件。

## 正式窗口输入

隔离 Windows Desktop/MCP 使用现有账号和设备密码，通过正式 AI 协助提示打开
Apple 的独立远程桌面窗口。人工核对当前画面是自建 AppKit 测试窗口后，点击
「启用操作」。输入经 Windows 原生子窗口、产品协议、Apple helper 和原生输入
worker 到达测试窗口；没有直接向远端测试窗口注入事件来代替网络链路。

| 操作 | Apple 测试窗口观察结果 |
| --- | --- |
| 点击 view 内 (100,100) | 按下/抬起各 1 次，实际 (99,101) |
| A 键按下/抬起 | 各 1 次，Mac keyCode 0 |
| 滚轮 | 1 次 |
| 按住 Shift | shift_down=1、shift_up=0、shifted=true |
| 关闭正式远程窗口 | shift_up=1、shifted=false，协助 active→waiting |

每次操作前检查同一 PID、报告新鲜度和目标窗口焦点。测试全程没有额外 GUI
抢走焦点；关闭后的实际按键释放由远端 fixture 再次读取确认。

## 动态显示

新增 `experiments/remote-desktop/macos_display_fixture.m`，以单个 clang 编译进程
通过 `-Wall -Wextra -Werror`（忽略系统绘制回调的未用参数）。AppKit 窗口在
既有单屏 1920×1080、1× 缩放条件下绘制全屏变化色块和 12 位帧号/反码，
不修改显示模式，120 秒自动退出。本轮显式提前停止。

正式窗口请求 15 FPS，观察到实际动态画面后，用既有 Windows compositor/GDI
采样器读取原生显示表面。只保存帧号和时间，排除重复帧、遮挡、反码不匹配及
倒退；不是按解码回调或请求帧率计算。

- 采样时长 30.0064 秒，1330 次采样，448 个不同显示帧号。
- 无效采样 0，重复采样 882；实际采样率约 44.3 Hz。
- 排除最初 3 秒后，按完整剩余窗口计数，**14.8853 FPS**。
- 最长显示间隔 0.116427 秒；通过 >12 FPS 的本次动态基准。
- 源画面 1920×1080，Windows 原生表面 1650×1032，按比例显示并有黑边。

原始帧号/时间和输入计数见 [机器记录](remote-desktop-macos-network-input-2026-10-17.json)。

## 环境恢复与范围

继续使用 7 分钟候选期限、独立 8 分钟回滚作业的临时服务安排，固定已授权
helper 路径和签名。仅复制设备身份/认证到隔离数据库，旧 env 只解析为 TOML，
原安装配置、数据库及应用文件不覆盖。测试后原服务恢复 PID 58724，原设备
认证记录一致，安装文件哈希不变，候选/fixture/动画进程及临时 launchd 作业为 0，
临时服务目录和远端测试窗口目录已删除。恢复后原服务的 native user 命令也通过。

测试前两次 user-context `stat` 返回 interrupted；第一次在服务切换期间，第二次
候选服务已连接。候选可执行文件当时位于仅 root 可遍历的临时目录，后续测试
准备通过服务端 launchctl/sudo 进入明确的 uid 501 完成。已调整下次隔离脚本的
可执行文件位置，身份材料仍在 0700 私有目录；该脚本调整尚未单独重测，不能
把此次成功计作候选服务的 native user 命令回归通过。

后续 [Linux → Mac 产品验证](remote-desktop-linux-to-macos-2026-10-17.md) 已在同一
候选 Executor 哈希、可遍历外层目录下，通过 native user context 执行
`/usr/bin/id -u` 得到 501。此项只补进程创建路径，未宣称全部用户命令回归。

本轮没有验证双击、拖拽、输入法、混合 DPI、多屏、Mac 操作端方向、锁屏/系统
登录、Direct/Relay 分类、弱网或长期稳定性。W4/W7 仍未完成；没有发布安装包。
