# 人用流式远程终端：90 可行性论证

结论：三项前期原型验证已通过，可以进入独立功能开发。该结论只涵盖本次 Windows 90 的基础技术组合，不代表新人用终端功能或其完整安装版验收已经完成。

## 原型与保护范围

- 目标：90，设备码 428358431，Windows x86_64，系统版本 10.0.20348。
- PTY：单独编译、单独运行的 portable-pty 0.9.0／ConPTY 原型，创建持续存在的系统 PowerShell；分别以 SYSTEM 服务身份和 Administrator 用户身份运行。
- 传输：独立原型绑定远端回环地址，操作端通过同一 MCP 的三个端口转发，复用现有已认证 PAB 连接及独立 QUIC 流；全部观察到 direct 路径。测试同连接上的持续输出、控制及独立关闭，不新增公共服务。
- 前端：90 上单独的原生 Tauri／WebView2／xterm 窗口，使用真正的 Tauri IPC Channel 和渲染消费确认。此窗口与 PTY 的通信在 90 回环地址进行，尚未将前端与新人用协议集成到 PAB 正式路由。
- 本轮未修改 apps、crates、主 Cargo.toml 或主 Cargo.lock，未覆盖安装本机或 90 的产品。90 Executor 仍 Running，SHA-256 仍为 `436aaa7791ed3a3527903322b9303550a237b5a64abecaf5f1d24c4f5fc0d257`。所用 MCP 为已构建的 V1.2.97 组件，SHA-256 `b7acfe123b7f78bb0f13f642ed324325137a4e63ed92600af9be55651c6cbcdf`。

## 原始证据

- [Administrator 正式 PAB 连接原型结果](desktop-terminal-user-direct-2026-10-14.json)：已核对输出 18,083,959 字节，大输出阶段 17,820,710 字节；哈希 `665b572f5df89492a5bb22bb668335c3e7821cd07da75b8b6edff3456a698622`。输出暂停时稳定命令及稳定 MCP 终端均成功；Ctrl+C 输入确认约 23ms，结束 Shell 确认约 25ms。
- [SYSTEM 正式 PAB 连接原型结果](desktop-terminal-service-direct-2026-10-14.json)：已核对输出 18,084,090 字节，大输出阶段 17,820,606 字节；哈希 `8b41eb963a7256a7eac2aa8150461d31bb540eb9aad3e5a14c5957ea67572c96`。Ctrl+C 输入确认约 22ms，结束 Shell 确认约 25ms。
- [真实窗口小规模验证](desktop-terminal-webview-small-2026-10-14.json)：4,861,567 字节，隐藏及暂停后恢复，原始哈希一致，历史行数恒定。
- [真实窗口约 65MiB 验证](desktop-terminal-webview-large-2026-10-14.json)：源端 produced、acked，前端 received、consumed，原生接收计数均为 68,041,638；原始哈希一致。

原型的输入 ACK 表示 PTY 接受输入，不代表命令完成。Ctrl+C 的可用性还以同一个 Shell 后续执行标记成功为依据。上述 PAB 哈希对应大输出完成后的核对快照，强制结束时的后续控制／提示字节另记录在 final_stats，不能混用两个快照的哈希。

窗口 JS 堆样本为首轮后 36,516,981、第二轮后 45,082,592 字节，可能包含未回收的临时分配；未强制 GC，也未开展长时间泄漏测试。这里证明的是已消费历史和未消费输出的有界策略及短时行为，不把两个堆样本当作长期内存稳定的证明。

## 发现的问题与落实的设计

1. **只结束 Shell 不能可靠解除 ConPTY 阻塞读取。** 两种身份均复现。新增功能要求全部 PTY（包括服务身份）归专属 worker 进程所有，独立关闭可以结束该 worker；不得在稳定 Executor 主进程里等待阻塞析构。
2. **逐小块 IPC 和逐块 Promise 确认吞吐不合适。** 初始原型大输出未完成，修正为最多 16KiB／低速最多等待 10ms 的聚合，并只持有一个在途 ACK 与最新确认位置；重测原来的大输出目标通过。固定块上限、有界中间队列和端到端 256KiB 信用额度同时存在。
3. **聚合超时不能取消半帧网络读取。** 原型使用独立完整帧读取任务，再对安全的 mpsc 接收施加聚合超时。
4. **Windows 短 TCP 帧的包装会影响样本。** 包装原型曾出现一次大输出超时；关闭该包装层的 Nagle 延迟后，最终 user／service 重测通过。正式方案直接使用 QUIC 帧；该样本不替代正式链路的异常测试。
5. **初始测试屏幕采样漏掉顶部行。** 等待标记的脚本只检查底部 30 行，在更高窗口漏掉已显示的顶部内容；修正为包含实际可见区域后通过。
6. **90 的运行时自动发现有环境问题。** 原型及一个既有 Pixels 窗口均提示无法找到 WebView2，虽然运行时文件存在。原型仅在自己的进程内指定已有 `154.0.4258.62` 目录，未修改注册表或系统安装。该参数的用途见[微软参考](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/webview2-idl)。产品的环境错误处理须纳入后续窗口安装验收。

原型与重现说明见 [独立项目](prototypes/desktop-terminal/README.md)。两个 Cargo 项目均是独立 workspace，原生构建始终使用最多 18 个编译任务；不升级产品依赖。
