# Helper 码率转发与 90 实际限速验收

日期：2026-10-19。代码提交 `13fbe3f`，接续 `4c8fb4f` 的码率实现。未发布 COS，未更新本机安装版。

## 修复的问题

实机发现 NativeSource 虽然支持调码率，实际 Executor 使用的 HelperSource 没有转发这一能力，正式窗口因此报告编码预算不可用。现通过已有、经过身份验证的独立媒体 IPC 转发预算请求；helper 显式声明可选扩展版本后才发送新操作。旧 helper 不接收未知命令，原有 started/next 和外部视频协议保持兼容。

原生后端不能调整时仍保留原硬编路径；取消预算请求则退休这一条采集通道。四项真实 helper/socket 回归覆盖转发、恢复默认、旧端兼容、不支持时继续出帧及取消清理。

同一观看会话切屏/重建 generation 时，现保留码率预算和采集节奏；帧号、在途额度、旧输入仍清空。新编码器在首帧前应用已有预算。**完整断线后新 session 的预算延续尚未实现/验收，不能与这里的 generation 切换混称通过。**

## Windows 正式窗口：限速、切屏与恢复

90，1920×1080，15 FPS，D3D11 硬解，默认只查看。屏幕显示持续变化的生成色块和带互补校验的帧码；采样实际窗口合成像素，不使用接收包数或解码回调当显示帧。

只对独立目录中的候选 Executor UDP 出站设置 Windows QoS 350,000 bit/s，持续约 45 秒，由独立计划任务的 finally 撤销。未限制整机网卡、其他应用或已安装版。未注入额外 RTT。

| 阶段 | 实际显示 FPS | 有效生成帧 | 无效像素样本 |
| --- | ---: | ---: | ---: |
| 正常网络基线 | 14.85 | 148 | 0 |
| 350 kbps 限速 | 4.99 | 44 | 0 |
| 解除限速后 | 14.70 | 148 | 0 |

各阶段采样约十秒，FPS 排除前三秒预热。弱网阶段低于 12 FPS 属于明确降档；采样器保留原严格性能断言，因此该次退出 1，唯一阈值失败为 `observed_fps_not_above_12`。画面仍持续更新，无像素校验错误或采样异常，不能将这个退出码直接标作正常网络性能失败，也不能把弱网帧率算成达标基线。

51 次状态观察始终为 viewing、同一 session、input_enabled=false，编码尺寸没有改变。窗口出现实际 Reduced quality 标签，预算经过 3 / 1.5 / 0.75 / 0.35 / 0.15 Mbps。约第 25 秒重选同一屏幕，generation 1→2，首次新代观察仍为 150 kbps、采集上限约 8.14 FPS；最后恢复默认预算 0 和 15 FPS 上限。此处采集上限与实际显示 FPS 分别记录。

另一轮协调好的 45 秒限速中，普通命令查到启用中的策略，PTY 输出 `QOS_PARALLEL_ACTIVE=1`，观看窗口继续 viewing、只查看。终端正常关闭，策略撤销确认后再恢复原服务。未在本轮重测大文件传输，沿用已有回归范围。

## 保留的失败和边界

初次两项节奏测试使用每帧 512 KiB 的未压缩假负载，在未优化 QUIC 下未达到 12 FPS；独立复测也失败。现只将节奏夹具设为 16 KiB，以分离调度与调试版批量加密吞吐，原 512 KiB 大帧/额度测试和严格 FPS 阈值保留。最终 36 项通过不表示这个调试版大负载性能已修复，实际显示性能以上述原生窗口为准。

固定候选的两次采样曾被本机终端遮挡，分别产生全无效帧码或直接拒绝采样；保留失败文件。有效轮仅临时置顶自己的隔离窗口并在结束后恢复原状态。并行终端初次观察恰逢测试服务十八分钟自动回滚，旧 PTY 失效；该轮未算通过，随后在新协调窗口中重测命令及 PTY 成功。

原有独立高熵软件编码错误仍未定位。完整新 session 的低带宽首帧/重连、RTT 与路径变化、Mac/Linux 新 helper 实际运行、最终三平台候选与安装仍待后续；30 分钟混合和 100 次开关绑定最终候选重做，2/8 小时仍按用户安排留到晚上。本轮不新增显示缩放，不扩大鉴权和使用限制。

90 原服务命令与 Running 状态已确认恢复，PID 16684；临时策略、计划任务、采集进程均为零，输入释放标志为零，远端测试目录删除完成。Linux 原服务未切换，生成窗口/worker 正常退出，三个临时文件及目录删除完成。隔离 Desktop/MCP 已退出；本地私有验收缓存和 Apple 持久构建缓存保留，不等同于全部临时目录已删除。
