# E3 文件工具执行身份接入记录

## 已实现

- 12 个现有文件工具（stat/read/write/patch/search/hash/mkdir/copy/move/delete/ZIP 创建与解压）增加 execution。缺省 service 保持原参数序列化和指纹；user 使用当前连接的 context_ref，要求 filesystem v5。desktop_user、用户名/密码等伪造身份字段拒绝。
- 新请求接受前复核原生身份，在同一 SQLite 事务保存待执行记录及实际 execution_context。相同请求查重先于新连接引用解析；重复 ID 不重做，修改 execution 产生请求冲突，读取内容仍沿用原 read_request_consumed 约定。
- 用户操作路由到已验证的 FileEngine/user-worker；哈希与批量操作复用既有 4 槽配额、任务注册、取消和独立观察。服务执行也保存其现有执行环境。
- 未确认文本发布按原记录中的 UID/SID/会话只读核对大小及 SHA-256，不依赖新连接引用。原用户无权限或已不可用则保留未确认，绝不改用服务权限读取。
- Bridge 本地记录保存完整结果中的实际身份；收到后续身份变更或身份字段被清空时拒绝更新。
- 文件流入口把无效用户上下文等错误返回为结构化响应，避免客户端只看到断流；明确的 EnvironmentChanged 接受拒绝记录为失败，传输丢响应仍保留未确认。
- MCP 目录校验统一调用全部文件工具的现有类型解析器，执行模式和字段形状在发送前校验。复用 serde、Tokio、现有原生用户后端和文件实现，无新常驻服务或逐项审批。
