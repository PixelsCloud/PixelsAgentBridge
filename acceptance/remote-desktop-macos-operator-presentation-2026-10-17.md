# Mac 操作端：实际合成画面帧率

日期：2026-10-17；基线 `0f1167c`。Apple macOS 27.0.1 arm64、1920×1080、1×，
通过既有认证和可靠传输，在正式独立窗口观看 90 的 Windows Server 2022 桌面。
正式 Desktop 构建、签名和窗口布局沿用
[操作端验收](remote-desktop-macos-operator-layout-2026-10-17.md)，本轮未改产品代码。

## 方法和结果

90 运行独立的 1080p 自生成动画，30 FPS 更新颜色格和 12 位帧编号，另有反码行、
四个固定校验位；不采集用户内容、不发送输入、不改变分辨率，120 秒自动退出。
Mac 通过真实 AI 协助提示打开产品窗口，保持仅查看，分别选择 15/30 FPS。
观察器从 Mac 已合成桌面另行采集，硬件编解码后只读取 32 个亮度点。
它不统计产品的解码/提交回调，不把编号跳跃补为未观察到的帧，不存储视频。
观察器每 15 个样本核对拥有窗口的 PID、窗口 ID、位置和尺寸；采样范围包含黑边
时按实际显示比例定位编号。使用同一已批准测试包启动观察采集，未再次要求授权。

| 项目 | 15 FPS 窗口 | 30 FPS 全屏 |
| --- | ---: | ---: |
| 测量时长 | 30.002 秒 | 30.018 秒 |
| 采样数 | 1405 | 899 |
| 独立观察到的新编号 | 444 | 899 |
| 无效编号 / 重复编号 | 0 / 961 | 0 / 0 |
| 去除前 3 秒后的接收计数率 | 14.999 FPS | 30.017 FPS |
| 含启动/尾部的观察到的变化率 | 14.766 次/秒 | 29.916 次/秒 |
| 最长观察间隔 | 94.8 毫秒 | 58.4 毫秒 |
| 原采样器结论 | 通过 | **失败，保留原结果** |

15 FPS 档在本机型/网络基线下完成实际显示超过 12 FPS 的验收。这里的性能包含
额外观察采集与硬件编解码负载，不能外推到全部机器或最终发布包。

30 FPS 全屏失败的具体条件是 `samples / seconds >= 30`：实际为 29.949 Hz。
其他两个原检查（有效新画面速率 >12、无效样本比例 ≤5%）通过。
保留原始 `passed: false`、失败任务及完整样本，不把复核程序退出成功解释成
原测试通过。原观察器请求 60 FPS，并不能证明它实际交付 60 FPS 样本。
代码 `capture.h` 只接受 `SCFrameStatusComplete`，配置的是最小帧间隔；
全屏观察结果与按变化交付约 30 FPS 的情形一致，但本轮没有记录全部系统回调，
所以不能断言闲帧过滤是唯一原因。仍需完善观察覆盖检查再重新完成全屏验收。

复核程序同时保留原检查，另计算 `(观察到的新编号数 - 1) / 时间区间`；区间取
完整接收观察时长和采集时间跨度中较大者。不同进程的两个时钟只分别计算跨度，
不直接相减。此统计仅报告实际观察到的变化，不声称准确刷新频率、丢帧比例、
端到端延迟或无卡顿。编号校验不是图像颜色质量验收。

## 可复核资料

机器与构建哈希、任务状态、截图摘要、恢复结果见
[汇总 JSON](remote-desktop-macos-operator-presentation-2026-10-17.json)。
原始报告从远端下载后逐字节保存，SHA-256 再与远端核对；内容仅为生成编号、
时间和测试元数据，不含图像、用户输入或配置凭据。

```sh
python experiments/remote-desktop/analyze_macos_presentation.py \
  acceptance/remote-desktop-macos-operator-presentation-2026-10-17/15-window.json \
  acceptance/remote-desktop-macos-operator-presentation-2026-10-17/30-fullscreen-observer-guard.json
```

观察器 native 工具在 Apple 串行单任务编译；Windows 动画单翻译单元编译，编译器
及子进程限制一个逻辑核。这两次构建不同时执行，没有重编或替换本机安装版。
工具源文件为 `macos_sample_codes.mm`、`macos_sample_presentation.py` 和
`windows_display_fixture.cpp`，均位于 `experiments/remote-desktop/`。

首个采样启动方式从 Python 直接派生候选二进制，权限预检查失败并退出；未弹出
新授权要求。随后改为 LaunchServices 启动同一个固定路径、固定签名的已授权 App，
成功采集。这是测试启动身份差异，不据此判定用户未授权正式 App。
