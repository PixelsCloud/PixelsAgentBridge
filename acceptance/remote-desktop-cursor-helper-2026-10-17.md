# 独立光标 helper 通道

延续 [光标会话阶段](remote-desktop-cursor-session-2026-10-17.md)。本阶段把
DesktopBackend 的光标源接到现有本地 helper 传输；系统采样和窗口绘制尚未
接入，不关闭 LT-03.5，也不宣称产品已显示独立光标。

## 实现

- 复用本地 IPC 认证及现有内核进程身份验证。新光标 socket 必须属于采集注册
  的同一进程，provider_id 自身不授予访问权，不增加用户密码或独立鉴权流程。
- 绑定采集的完整 active_config，包含 session、generation 和屏幕布局。
  注册光标时检查采集能力与进程身份，启动和每次读取都检查配置仍匹配。
- 视频、输入和光标各用自己的请求通道；光标最多一个未完成的拉取请求。
  画面静止或视频展示额度耗尽不会阻塞光标。源仍须保留最新快照，不能缓存
  全部历史移动；这一原生实现要求尚待后续接入。
- helper 与 Executor 两端验证图像大小、顺序、图像引用和代次，接收端在
  分配像素前验证头部。最大图像 2 MiB，二进制分块不超过 64 KiB。
  等待静止光标允许空闲；收到图像头部后，剩余像素传输有 5 秒时限。
- 丢弃源、取消启动或取消已派发的读取会关闭光标 socket；视频和输入保持。
  采集关闭、进程身份失效或会话退出会取消光标，包括正在等待的源。
- HelperMediaBackend 的光标能力优先跟随正在采集的 provider；有新 helper
  注册也不改变当前窗口的能力。没有活动采集时，按现有选择顺序并保留 Linux
  supervised 优先级。不支持或未知版本不公告能力，不影响旧 helper 的视频。
  当前生产 NativeBackend 仍未实现系统光标源，因此仍不公告支持。

## 验证范围

本地真实 WebSocket 及内核 PID/账号身份检查，使用生成的光标图像；没有采集
用户桌面、发送真实系统输入，也没有替换本机安装版或任何远端服务。
外层本地 IPC 认证沿用已有实现，新的通道配对测试不冒充端到端 GUI 验收。

新增测试覆盖：

1. 视频读取保持等待，2 MiB AND/XOR 图像及负原点热点仍能通过独立通道；
   后续隐藏/移动不重传图像，未请求时不拉取下一份，键鼠通道继续工作。
2. 错 provider、重复通道和旧代次/布局拒绝；关闭采集使保留的光标失效，
   新代次从序号 1 和新图像开始。
3. 在源实际启动后取消启动、静止读取中取消：原生测试源释放，只关闭光标，
   原视频仍可返回下一帧。
4. 直接从模拟 helper 发送超大尺寸、错代次/序号、未知图像引用，不发送任何
   图像数据即可验证接收端拒绝；半份像素超时、超过剩余长度的分块也拒绝。
   每种失败后视频继续工作。
5. 不支持独立光标的旧 helper 不公告能力，不能附加光标，视频正常。
   新旧 helper 交替注册期间，能力跟随当前采集；关闭后切到旧 helper 则撤回。

## 验证结果

```text
cargo test --locked -p pab-executor --lib local_ipc::media::tests -j6
8 passed; 0 failed

cargo test --locked -p pab-executor --lib local_ipc:: -j6
39 passed; 0 failed
```

39 项包含前面的 8 项，不重复计数。最终回归包含活动采集能力保留及关闭后
回退的修改，另覆盖既有 IPC 身份/账号、窗口、截图、大图二进制、输入和凭据
刷新逻辑；均为隔离测试环境。新文件 rustfmt 检查与 git diff --check 通过。

本轮 Cargo 6 jobs，嵌套 CMake 1 job、MSVC /MP1、测试线程 2。首次检查没有
其他构建；回归前发现未确认预算的原生构建，脚本拒绝启动。随后重新检查仅
有另一个明确 -j 2 的 Cargo 构建，按合计 8 jobs 启动，没有终止他人的任务。
记录位于 `.build/remote-desktop/cursor-helper-tests.log` 和
`cursor-helper-ipc-regression.log`。

未运行本阶段的 Mac/Linux 实机、系统光标、窗口绘制或网络长稳验收；此前
其他阶段的通过结果不替代这些项目。

## 后续

然后完成原生窗口叠加、缩放/热点/裁剪、反色、隐藏和切屏清理，并做多屏、
登录场景与性能验收。Mac 本轮按用户确认的单屏条件执行。
