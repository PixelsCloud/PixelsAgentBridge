## 已修正：保留具体异常

原 Windows worker 在 interactive 模式下把 stderr 用作二进制输入事件通道，
但异常处理仍向该通道写普通文本。Rust 读取器将其当成无效输入包，导致
具体渲染错误被泛化为管道错误。

现在异常在输入通道使用有界、带长度的专用错误包；最多 512 字节，非法长度、
格式、UTF-8 或截断均失败关闭，不生成输入。第一条失败原因保留，后续 EOF
不能覆盖它。呈现通道也使用已有错误事件，避免两个读取器竞争时丢失原因。
不改变网络协议、远端鉴权、图像编解码、帧率门槛或输入重放规则。

验证：

- 旧正式 Desktop 的独立原生 worker 接收测试用超长帧头，退出码 1，stderr
  为 `Render packet too large` 普通文本，复现旧缺陷。
- 新原生 worker 同一输入，两个通道均返回对应的有界错误包，退出码仍为 1。
- 完整 Windows Desktop 构建通过（Cargo 2、原生 1），其内置 worker 的相同
  错误包验证也通过；没有只测试与 Desktop 不同的独立二进制。
- 媒体模块 27 项测试通过；手动性能测试 1 项保持忽略。其中新增测试覆盖
  异常后 EOF、待处理按键不能继续投递，以及非法/截断错误包。
- 第一次诊断脚本遗漏既有私有协议版本头及 Windows CRLF，断言失败；原始
  输出保留，修正脚本后另建结果文件，未覆写原记录。

该修正解决诊断丢失，不证明此次长测的原生退出根因已解决。需用新候选重现。
