# 修复候选的连续开窗与混合采样

日期：2026-10-18。源码基线 `084b674`；产物哈希、各轮数据和恢复结果见
[结构化记录](remote-desktop-candidate-sampling-2026-10-18.json)。

固定候选包含 Linux 进程身份持有与订阅最终快照两项修正。首先独立打开、采样、
关闭五次正式窗口，均为不同视频会话；五次实际帧码采样通过，关闭确认通过。
这没有重现前一轮首次采样的无效帧码，也不能反证原失败不存在。

随后用同一候选新建视频与一个终端，申请运行 1800 秒混合业务。每 30 秒在
上传 4 MiB、命令校验、原终端标记和下载校验的同时采样 10 秒实际呈现。
前五轮分别为 14.56、14.43、14.57、14.56、14.56 FPS。第六轮所有业务操作
完成，但实际显示仅 10.83 FPS，低于既定门槛，因此整个测试失败。

第六轮共 598 个采样，零无效帧码、零帧编号倒退；最长呈现间隔约 201 ms。
虚拟机 CPU 忙碌率从前五轮的 53%～58% 升至约 77%，源图案生成仍约 29.20 FPS。
这只说明降速发生时有负载变化，未定位采集、编码、传输或显示中的具体原因。

本轮 Windows 主机同时运行了 AI 协助界面回归和两作业 Cargo 检查，没有记录
主机全局 CPU 时间序列，不能将下降归因到单一组件。下轮性能对照须避免这些
并行任务，并补主机全局负载；不放宽 FPS 门槛，也不重放未确认的终端输入。

已停止独立 Desktop 并核对其路径下没有存活进程；Linux 原服务以 PID 56999
恢复，配置和 unit 校验保持，原 Wayland 会话未锁定，显示恢复为 1694×1102。
测试 stage、fixture、输入设备及校验过的 payload 清理完成。历史 exec handle
在上下文恢复后不可查询，故仅记录实际进程退出核对，不编造它们的退出码。

此轮未达到 30 分钟，不关闭长期稳定性、原终端持续存活或订阅修复的实机长稳
验收。2 小时、8 小时和发布仍未完成，完整关闭数保持 11/53。
