# Linux 控制台媒体监督与会话交接

日期：2026-10-17，基线 `71761c9`。
[机器记录](remote-desktop-linux-supervisor-2026-10-17.json)保存产物哈希、通过项、
失败轮次和恢复结果。本阶段完成自动媒体 helper 生命周期及隔离的生产 IPC
交接测试，尚未完成正式窗口内的系统密码登录。

## 实现

Linux Desktop 新增 root 服务入口 `--media-supervisor`，从 logind 观察 seat0
当前本地图形用户或 greeter。通过实际 PID、UID、进程生命周期和会话重新核对，
读取对应图形进程所需的 DISPLAY、XAUTHORITY、D-Bus、Wayland 环境；不复制
整个环境，不执行登录脚本，不从环境声明获取身份。现有命令执行路径保持原样。

root 进程只负责生命周期。采集、编解码和输入仍由降权后的实际用户 helper
运行，使用既有本地访问凭据和内核身份校验。每次启动创建独立运行目录，数据
目录权限 0700、访问凭据 0600；root 拥有外层目录和原子写入的 owner 元数据。
这里的 JSON 是进程生命周期运行数据，不是应用配置，应用配置仍使用 TOML。

一次只监督一个 helper。切换时先停止并回收原 helper，再启动新用户的 helper；
复用现有进程组回收。降权后设置 Linux 父进程死亡信号，避免监督进程异常退出
留下 helper。独占文件锁避免重复监督进程，重启检查原进程身份及数据使用者后
清理遗留目录。

Linux 媒体循环改为协作退出：关闭媒体请求后等待采集、输入 watchdog 的回收
和按键释放完成，再让 helper 退出。启动注册前执行已有输入恢复。监督进程
提供 15 秒清理时间，systemd 停止超时为 20 秒，保留有界强制回收。

Linux 桌面包增加媒体服务，随 Executor 启停；安装、升级、卸载脚本接入该
服务。切换到无桌面的安装包时先停止并禁用媒体服务，再删除图形程序。

## 实机和构建验证

- 完整 Linux Desktop Release 构建通过，Cargo 4 jobs、嵌套原生构建 1 job。
  产物 SHA-256：`30dea5f6eb771b92c7f9c8ed8db4c2b2e935efb0dc76f27fc0e9365015c4a51c`。
  Executor 验收程序使用 2 jobs、嵌套 1，未与其他编译叠加超过 10。
- OS-control 的 16 项测试通过，包括图形会话策略、环境筛选、内核身份、原有
  用户进程启动和进程组回收测试。
- Ubuntu VM 独立 systemd 测试单元运行生产本地 IPC 服务、实际 Desktop 监督
  进程和 helper。使用独立数据及临时端口，不替换已安装 Executor，不连接
  外部控制服务，不使用安装版的本地访问 token。
- 普通 Wayland 用户 UID 1000 → Xorg GDM UID 128 → 原用户的三个阶段均通过
  HMAC 本地认证、实际 PID/UID/logind 身份校验、1314×742 采集/解码和原生输入。
  每次切换后旧媒体读取和旧输入操作均被拒绝。
- 在 GDM 按住左 Shift，独立 Xlib 进程查询确认实际按下；离开 GDM 后同一
  观察进程确认实际释放。没有用输入 ACK 替代操作系统状态检查。
- 单独生命周期复验通过：拒绝第二个监督进程和普通用户直接启动；原 helper
  与私有目录在两次交接后均消失；观察到的 helper 数量最大为 1。仅杀死测试
  监督进程后，其 helper 退出；重启自动清理遗留目录；正常停止回收 helper。
- 四个安装脚本通过 `bash -n`，打包 Python 语法检查通过；两个服务单元通过
  VM 的 `systemd-analyze verify`。输出另有 VM 现存 snapd.service 的不相关
  RestartMode 警告。尚未把这些检查计作实际安装升级验收。

## 失败与修正记录

第一轮三阶段 IPC 测试本身通过，但独立观察发现离开 GDM 后 Shift 仍处于按下
状态，因此整轮判失败。检查发现原 helper 直接中止循环并退出，没有等待异步
输入清理完成。补上协作退出、回收等待和启动恢复后，最终实机轮次确认释放。

中间一轮在 GDM 启动期间输入通道关闭；另一轮实际获取到 Wayland greeter，
没有满足所需的 Xorg 条件。GDM 日志出现 `Session never registered` 和显示
失败回退。测试增加 GNOME SessionManager 完成启动的同步点，并清理明确由
失败测试遗留、非活动的 c12 greeter，再复验。没有把这些失败隐藏为通过，也
没有将 Wayland 回退结果当作 Xorg 验收。

每轮切换前建立独立恢复计时器；临时 `/run/gdm3/custom.conf` 仅用于本次测试
偏好 Xorg，结束后删除并重载。系统 `/etc/gdm3/custom.conf` 哈希不变。最终
两轮各持续观察 15 次，活动会话始终为原 hy/Wayland 会话 13，且未锁定。
最终复查临时媒体进程、测试恢复目录和监督运行目录均为零，原 Executor active。
没有修改自动登录设置、用户密码或本机安装版。

## 后续边界

本次通过的是实际会话交接与生产本地媒体通道，不包含外部网络、正式独立观看
窗口内的连续系统密码登录、安装服务升级或新用户登录。Wayland 锁屏/GDM 的
PipeWire 禁止问题仍未解决。W5、W7、W8 保持未完成；后续继续接入安装服务、
正式窗口登录、Wayland 登录媒体以及最终持续运行与发布验收。
