# Mac / Linux X11 操作端：Windows 锁屏登录与恢复

日期：2026-10-20。基线 `d81d74e`。本批新增 Mac→90、Linux X11→90 的正式产品窗口锁屏登录证据，
并修复一次实际观察到的登录后画面停止自动恢复。结果、源码/产物哈希及原始材料索引见
[结构化记录](remote-desktop-operator-windows-login-recovery-2026-10-20.json)。

## 修复的问题

修复前，Linux 产品窗口输入一次密码后，90 已解锁，但源窗口停止恢复：

```text
recoverable=false error=remote desktop InvalidRequest:
remote desktop stream ended or was cancelled; open a new generation
```

`DesktopError::Closed` 和 `Timeout` 在本地均可恢复，但服务端 `code()` 的默认分支把它们编码成
`InvalidRequest`。登录桌面交接时旧 helper/视频流退代，控制请求碰到该边界，远端客户端便会当作永久错误退出。

现在 `Closed` 返回已有的 `StaleGeneration`，`Timeout` 返回已有的 `MediaUnavailable`。
客户端沿用现有重试间隔、120 秒恢复上限和只查看门控；没有新增协议枚举、鉴权流程或输入重放。
`InvalidRequest`、WrongOwner、Busy、Unsupported 等原拒绝语义保持不变。

Mac 恢复图像由其自有产品窗口采样，未把另一个操作端或恢复脚本的成功当作 Mac 登录通过。

Mac 的最终实体键夹具使用已有原生媒体输入驱动，路径为：
Windows 测试夹具 → Mac 本地输入 → **Mac 产品窗口 → 90**。
Windows 夹具没有直接向 90 注入登录按键。额外的 Mac 被控媒体后端仅用于向操作端注入实体键，随后恢复。
密码只在已有 DPAPI/内存与受限临时输入通道中使用，验收文件没有口令或键序列正文。

这些结果是现有会话的锁屏密码解锁。没有新增 Mac/Linux 操作端发起注销、重启或其他账号切换的通过声明；
登录后本次补的是显示恢复和操作开关，不把它扩写成完整目标应用输入矩阵。

## 保留的失败和环境修正

- Mac 初始测试命令的工作目录不可读；随后旧安装配置路径与上传文件属主也需调整。
  旧 env/JSON 只做静态解析，新测试配置均为 TOML，未执行或改写已安装的旧配置。
- 过长测试目录触发 macOS Unix socket `SUN_LEN` 限制。失败目录保留，改用新的短测试目录；原临时槽已撤销。
- Apple 初次锁屏，由用户解锁后继续。自有 AX 查询无法遍历 WK 内容，改用自有窗口图像和鼠标；
  standalone 媒体 worker 的 input CLI 不适用，未把其失败当作产品输入故障。
- 首次 Mac 用旧字符注入接口驱动原生实体键窗口，得到一次密码错误；结果保留，不计通过。
  最终采用已有媒体实体键注入后一次登录成功，没有为此修改旧输入接口。
- 实体键准备期间有一次夹具到时退出，未提交密码；随后一轮恰遇目标候选自动恢复原服务，
  得到 Unsupported，保留为环境中断。重新安排有足够时限的最终一轮后通过，未自动重放不确定输入。
- 一次本地切换脚本在执行前语法失败，后续 shell 初次重新启用了旧候选；恢复原服务并逐项核对后才做守卫下的候选切换。
  活动输入期间读取恢复状态文件曾遇共享冲突，没有据此推断按键已释放。
- PowerShell 对 Cargo stderr 的包装曾返回非零，而 Cargo 日志已显示构建完成；随后 Python 子进程确认增量构建退出码 0。
