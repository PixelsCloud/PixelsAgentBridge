# Windows 独立光标：90 实际产品窗口验收

产品基线 `8218d64`。接续 [本机原生渲染验证](remote-desktop-windows-cursor-render-2026-10-17.md)。
本轮通过实际 Desktop 独立窗口、既有设备认证、可靠连接、服务/helper、DXGI
光标源和 GPU 叠加，验证 Windows 普通单屏桌面的光标闭环。
机器、产物哈希、坐标与像素结果见 [结构化记录](remote-desktop-windows-cursor-product-2026-10-17.json)。
LT-03.5 和 W2 仍未整体完成。

## 环境与方式

- 操作端：Windows 10 19045，3840×2160，150% DPI；本机隔离 profile 和候选
  Desktop/MCP，未替换安装版。真实原生 surface 为 1650×1032，可见画面为
  1650×928，上下有黑边，验证了缩小显示和本机 DPI 对坐标的影响。
- 被控端：90，Windows Server 2022，1920×1080，100% DPI，Default 用户桌面。
  本轮实际枚举一块屏幕，不作为双屏证据。
- 服务与 helper 从唯一临时目录启动；使用原配置，提前注册有截止时间的恢复
  任务，保留原服务命令；每个上传文件由两端 SHA-256 核对。
- 测试窗口仅在自身客户区设置箭头、32×32 彩色光标、32×32 AND/XOR 光标和
  隐藏状态。顶部生成色条持续变化；记录自身点击、F24 和光标坐标，不记录
  用户文本，不安装全局钩子。源码为
  [windows_cursor_fixture.cpp](../experiments/remote-desktop/windows_cursor_fixture.cpp)。

## 结果

四个位置的目标/实际坐标分别为 `(471,551)→(471,550)`、
`(797,551)→(797,550)`、`(1123,551)→(1122,550)`、
`(1449,551)→(1448,550)`，每轴误差至多 1 像素。前三个位置显示对应光标，
第四个位置隐藏，窗口截图没有上一位置的残留光标。

像素检查使用第四张无光标截图作为同一固定客户区的背景，以远端独立读取的
系统热点位置、测试图案与本机窗口几何计算预期颜色：

| 光标 | 热点 | 检查像素数（含周围背景） | 不同像素数 |
| --- | --- | ---: | ---: |
| 彩色与透明 | 5,7 | 1,089 | 0 |
| 黑、白、透明、背景反色 | 8,8 | 1,056 | 0 |

这是经过真实采集、网络和产品窗口后的比较，不是直接向 renderer 输入生成
光标。截图保留在私有验收目录，不将远端用户桌面图片提交到仓库。
[比较脚本](../experiments/remote-desktop/compare_windows_cursor_fixture.py) 读取实际
截图、远端位置和窗口几何；不会把视频帧计数用作光标正确性的证据。

本地指针观察：将指针短暂移入自有窗口后，启用操作时 `CURSOR_SHOWING=0`；
停止操作后为 `1`。退出观察时恢复之前的位置；没有注入本地点击。

结束唯一的候选远端光标 worker 后，本地箭头恢复为可见，原会话仍为
`viewing`，session/generation 不变，输入仍启用。继续移动后，远端实际位置
到达 `(1448,550)`，视频色条仍变化，旧光标图像被清除。关闭窗口后没有
光标 worker；重新打开得到新 session，默认只查看。再次启用操作后，彩色
光标重新显示。最终关闭再次确认光标 worker 为零。
另对原彩色光标的 1,089 像素区域比较：故障后的截图与无光标背景完全一致，
重开后的截图与原彩色光标截图完全一致，确认清除和恢复均发生在实际呈现中。

### 尚未通过的输入项

首次激活测试窗口时，只发送了一次鼠标按下/释放，远端记录了 **两次按下**，
位置均为窗口中央 `(960,540)`。随后 F24 按下、释放各一次。这再次复现了
[既有 Windows 激活问题](remote-desktop-windows-controls-2026-10-17.md)，不能
把本轮光标通过写成完整键鼠通过，也没有修改输入语义来掩盖重复事件。

## 构建与清理

配套 Executor/MCP 构建通过，Cargo 6 个作业，嵌套 CMake 1 个，C++ `/MP1`。
测试窗口以独立 MSVC 单核心构建，最终源码另经 `/W4 /WX` 检查通过；并行
编译总分配不超过 7。通用构建入口
`python experiments/remote-desktop/build_windows_cursor_fixture.py` 会在其他
构建进程存在时拒绝启动；本轮还观察到空闲 MSBuild 复用节点会触发这一保守
检查，故严格警告编译使用已核对预算的单核心命令完成。

90 已恢复原服务命令且正常运行。临时服务程序、光标/媒体进程、测试窗口、
计划任务和远端目录已清理；最终只读检查为 Default 桌面、无测试进程。
本机候选 Desktop/MCP 已退出。递归删除测试 profile 被自动审批拦截后，改为
逐个删除已核对的账号、数据库、私钥和配置副本；受限访问的 WebView 缓存、
日志和验收截图继续保留，没有声称整个本机目录已删除。

仍需完成：首次激活重复按下根因、真实多屏/旋转/混合 DPI/热插拔与登录界面
光标、Mac/Linux 光标源和显示、动态视频与光标同时更新的帧率及资源验证。
本轮色条变化不计为 >12 FPS 的新证据，也不代替弱网、长期稳定性及最终安装包验收。
