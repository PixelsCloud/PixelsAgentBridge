# 操作端服务器覆盖与切换验收

日期：2026-10-15。源码改动未发布、未安装到本机 Pixels；未修改 BJ-200M 上原有 Relay。

## 行为

- Desktop 只返回用户保存的 `operator-server.toml`，默认地址不回显；两项同时清空恢复安装/启动默认连接。配置读取失败时禁止空值覆盖；半填写与非法 URL 被拒绝。
- Desktop/MCP 共用覆盖解析逻辑。开发环境重启继承的覆盖环境变量不会被误认作默认地址；显式 `--config` 优先，设置页不能修改该进程的服务器。
- 设置页切换控制服务会取消 GitHub 登录流程，清除旧服务与目标服务的本地账号、活动令牌及待登出令牌。仅修改 Relay 保留账号。连接在重启后切换，AI 客户端中的 MCP 也需重启。
- 按控制 URL 隔离操作端数据库、设备密码、队列、历史、Desktop 访客密钥及 MCP 端点槽位。设置和机器级 Executor 数据不搬迁。旧版未标记服务器的根目录数据库保留原地，不自动导入；对应设备需登录同步或重新添加。

## 已验证

- 配置单测 11 项；账号清理及服务器命名空间相关核心单测 3 项。
- Desktop `cargo check` 与前端 TypeScript/Vite 构建通过。
- 设置/历史浏览器回归 15 项，包含简体、繁体、英文的默认空值、自定义地址保存、半填写拒绝、清空恢复和读取错误保护。
- MCP 真实 stdio 测试共 9 项已通过：第一轮 8 项通过，端点槽位测试因旧路径断言失败，更新隔离目录断言后该项通过；新增覆盖/恢复测试最终再次通过。包括崩溃后端点槽位复用和多进程隔离。
- BJ-200M（Ubuntu x86_64）启动两个临时控制服务，均使用本轮源码编译的 Server，独立 PostgreSQL 数据库与回环端口；Windows 本轮 MCP 通过 SSH 隧道连接。使用自签名临时证书，保持完整 TLS 校验。因远端比本机约快 10 秒，证书有效期覆盖两端时钟；未修改系统时钟或正式证书。
- A 注册账号后，清理本地会话并切换 B：B 无 A 登录态、不能登录 A 的账号；同名账号在 B 注册为不同 ID；两端访客密钥和操作端目录不同。
- 清理两端本地会话并将覆盖值清空：恢复 A，初始未登录，显式登录后匹配原 A 账号。原始结果见 `report.json`。

远端验收的本地会话清理通过原生 `account-store-probe delete` 调用设置页相同的 `AccountStore::clear_local_session` 实现；设置页表单使用 Playwright fixture 验证。没有在已安装 Desktop 上操作真实账号，也没有执行 macOS 原生验收或新旧服务之间的文件传输验收。临时测试服务、数据库容器、临时私钥、服务器配置和上传二进制已清理，原有 Relay 继续运行。

所有编译串行安排，每条命令不超过 10 个 jobs；Linux Docker 构建另有限制 `--cpus 10`，嵌套 CMake 并行度为 1。
