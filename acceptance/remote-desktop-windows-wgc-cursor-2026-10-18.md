# Windows WGC 与独立光标协调阶段记录

日期：2026-10-18。基线 `9ed8897`。长期要求仍为 10/53 完整关闭。
结构化证据见[同名 JSON](remote-desktop-windows-wgc-cursor-2026-10-18.json)。

## 实现

此前 90 的竖屏视频已能使用 WGC，但独立 DXGI 光标进程继续 ACCESS_LOST。
现在为每次原生采集生成独立 UUID，两个 worker 使用该会话 Windows 命名事件协调：

- 正常 DXGI 路径保持原行为。光标在同一普通桌面、同一屏幕布局上失去 duplication
  时请求 WGC；视频自己发生 ACCESS_LOST 也能通知光标。
- 视频主线程在等消费额度和等待桌面更新时都处理切换请求。只有 WGC 初始化成功且
  已关闭内嵌光标后才确认切换；光标此前不猜测系统光标是否与视频重复。
- WGC 状态下，通过 GetCursorInfo 读取全局位置、显示状态，读取/绘制小型光标位图。
  屏幕外或系统隐藏时发送隐藏状态。位置改变不重传图像，图像只保留最新版本。
  半透明 BGRA 与单色/彩色 AND/XOR 分别编码，图像限制 512×512。
- 仍检查输入桌面及屏幕几何变化；等待视频确认最多五秒。切屏、结束视频与取消继续
  沿用原 capture lease 和进程回收机制，不修改网络协议、认证或单观看者规则。
- 命名事件只位于对应 Windows 会话，使用原 helper 身份及默认 DACL，无配置文件。
  创建时拒绝已存在的同名对象；结束后内核句柄释放，后续代次使用新 UUID。

## 验证结果

1. Windows 媒体 23 项单元测试及 2 项原生光标检查通过。新检查使用自建 OS 光标，
   将传输格式在四种背景上的合成结果与 DrawIconEx 对比，包含黑白反色、彩色掩码、
   全透明、半透明及不透明像素、热点和尺寸。AND/XOR 精确相等，alpha 仅允许一阶量化误差。
2. 同一检查验证事件初始状态、请求/确认、重复 owner 拒绝、全部关闭后不可重新打开，
   同名重新创建时状态清空、非法 token 拒绝。没有安装系统光标或移动真实指针。
3. 90 的 (-1080,0)、1080×1920 Parsec 竖屏运行正式 NativeBackend 两代次：
   每代在没有请求视频帧时读取光标，随后取得 H.264 关键首帧；光标重开成功，
   结束视频但保留光标对象时，backend idle 能完成、旧光标不能继续读取。
   两轮日志均出现 WGC GPU 与 NVENC、无桌面 CPU 回读。原生程序正常退出。
4. 该实机检查中指针位于另一屏，报告 visible=false。因此它证明协调与回收，
   不证明可见系统光标形状、移动、旋转坐标或正式 viewer 已通过。
5. 新完整 Desktop 构建通过。Cargo 最大 3 jobs；生成窗口单编译器固定 1 核，
   本轮合计最高 4。旧生成窗口构建脚本原先只识别 -j2，因此在编译前拒绝当前 -j3；
   修正为解析实际 jobs 并保持合计不超过 10 后构建成功。没有放开并发限制。
