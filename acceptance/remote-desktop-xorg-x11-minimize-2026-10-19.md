日期：2026-10-19。源码基线 `7efc841` 加本轮 Windows 原生显示补丁。
本轮三组实际方向为 Windows→Linux Xorg、Linux X11→Windows、Linux X11→macOS。

## Windows 操作端最小化修复

修复前，确认本机前台窗口和原生显示区域拥有焦点，在远端自有测试区按下 Ctrl，然后最小化。
约四秒持续采样仍观察到远端 Ctrl 按下；恢复窗口并显式失焦后才释放。
这与单纯模拟输入到未聚焦窗口的早期尝试分开，后者没有作为产品失败依据。

Windows 原生显示区域属于媒体进程，其 Tauri 父窗口属于另一进程；父窗口最小化时，
原生子窗口不一定先收到 `WM_KILLFOCUS`。原显示循环检测到最小化后直接停止绘制，未主动释放输入。
现在在首次进入最小化或零尺寸状态时，通过既有 release-all 通道释放输入，再进入原有暂停显示逻辑。
不重复发送释放，不增加连接或鉴权逻辑，也不添加强制焦点或点击去重。

重建的隔离 Windows Desktop SHA-256：
`8be996596a4bb22954554b80be373d088f4c21c44098c8fb93f60a9448a68efc`。
两轮真实产品窗口复测均通过：Ctrl 单独按下，以及 Ctrl 与鼠标左键同时按下，最小化后首个远端采样均已释放。
第二轮先确认原生区域确实聚焦；恢复后同一视频会话仍显示并可输入。
固定标记输入、关闭时 Ctrl 释放、重开新会话默认只查看也通过。
采样间隔和 SSH 读取有延迟，不把首个采样时长当作精确端到端释放延迟。

构建采用最多 6 个 Cargo 作业、原生并发 1，使用 `tauri/custom-protocol`。
首次构建因当前进程 PATH 缺 NASM 在依赖检查时停止；补入已有 NASM 路径，等待本机另一项目的 10 作业编译结束后再构建，最终成功。
本机安装版未替换。

## Windows → Linux 普通 Xorg

在 GDM 选择 Ubuntu on Xorg，一次密码输入后进入 hy 的真实 X11 用户 session 22。
已有观看窗口自动恢复为 X11 屏幕，默认只查看。屏幕 `x11:0:Virtual1`、1280×800、100% DPI；
H.264 与 Windows D3D11 硬解，15 FPS 为配置值，本轮未重新测量动态有效 FPS。

使用 GTK 自有窗口，事件仅在测试区域统计，文本只返回长度、选区及固定标记是否匹配。

| 操作 | 系统侧结果 |
| --- | --- |
| 单击 | 1 down / 1 up，没有双击事件；目标约 `(300,100)` |
| 双击 | 新增 2 down / 2 up、1 个双击事件 |
| 拖拽 | 有按下期间的移动事件，结束后左键未按下 |
| 滚轮 | 测试区收到 3 个事件；文本滚动值由 0 增至约 208.64 |
| Ctrl+A、输入固定标记 | 选中全部 7599 字符，替换为准确的 18 字符标记 |
| 失焦、关闭 | 已观察到的 Ctrl 按下状态均释放 |
| 800×600、1200×850 本机窗口 | 点击分别到达目标约 `(901,100)`、`(400,120)`，按当前留白区域换算 |

GTK 夹具第一版读取 TextView 几何的 API 用错，未产出有效观察文件；修正夹具并重新开始计数后才做上述验收。
本轮没有多屏、旋转、输入法全组合或最终安装验证。

## Linux X11 → Windows 90

使用隔离 Linux Desktop，原生 GTK 显示区域为 1210×664，目标 1920×1080。
经定向协助提示打开正式窗口，默认只查看；显式启用后通过 Linux XTEST 系统事件进入原生窗口，再经现有连接发送输入。
目标为本轮创建的经典记事本；独立、有超时的观察器核验所属 PID 和窗口，未读取其他编辑器正文。

| 操作 | 观察结果 |
| --- | --- |
| 单击 | 选区 `[6,6]`，放置光标 |
| 双击 | 选区 `[0,11]`，选中首词 |
| 拖拽 | 选区 `[0,25]` |
| 滚轮三个刻度 | 首个可见行 0→9 |
| Ctrl+A | 选区 `[0,5922]` |
| 物理键输入固定标记、Enter 提交输入法候选 | 精确 18 字符、选区 `[18,18]`、无按键残留 |
| 按住 Ctrl 后最小化 | 先观测到 VK_CONTROL，最小化后为空 |
| 重开后按住 Ctrl 再关闭 | 重开默认只查看；启用、实际聚焦后按下，关窗后为空；协助回到 waiting |

首次最小化后的直接 XMapRaised 恢复尝试没有确认原生区域聚焦，测试驱动拒绝继续按键；
没有将该次计为恢复后输入通过。后续关闭并重开后完成关闭释放验证，普通 X11 最小化恢复仍需补验收。
连续记事本观察器在输入后停止更新，改用独立限时观察；首个限时脚本的 BOM 导致初始化语句报错，纠正后才计入后续结果。

## Linux X11 → macOS Apple 单屏

复用已授权的持久测试 App 路径和签名，未重新申请权限。目标屏幕实际为 1920×1080，
按正式窗口中的屏幕配置计算留白与坐标；没有沿用错误的历史尺寸。
AppKit 自有测试窗口第二轮结果：一次点击 down/up 对应视图 `(100,100)`；
A 的 down/up 为 1/1、Mac keyCode 0；滚轮 3 次；按住 Shift 后 A 的累计 down/up 为 2/2；
关闭观看窗口后 Shift up 增至 1，shifted=false，协助回到 waiting；Linux 注入的本地 Shift 也已释放。
这仅证明这些物理键和基本鼠标动作，不代表完整文本输入法、快捷键或系统登录验收。

第一轮 AppKit 夹具仍按原定 120 秒正常退出，后续陈旧探针被拒绝；原因是测试脚本替换超时时的方法名大小写错误。
保留第一轮有效点击记录，键盘及滚轮不计为通过；修正并重新编译自有夹具后完整重测。
夹具两次编译各 1 个作业；产品媒体 App 未重新构建或换签名。
