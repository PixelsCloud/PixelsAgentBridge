# Mac 锁屏持续采集与 Linux 码率恢复

整理日期：2026-10-20；实机观察发生于 10 月 19 日。基线 `592b13a`，另含本轮采集期间显示器唤醒保护。
源码、构建、帧码采样、质量状态和恢复记录见[机器数据](remote-desktop-display-wake-recovery-2026-10-20.json)。
本轮补已有 LT-06.1/06.3/06.5/06.6，不新增功能要求；53 项总计仍为 18 已关闭、32 部分完成、3 交付待验收/执行。

## 结果

| 范围 | 实际观察 | 限制 |
| --- | --- | --- |
| Mac 锁屏持续显示 | 新包在未运行临时 caffeinate 的情况下，连续 45 秒、88 次观察均为同一视频 session，已出画面、只查看，无重连；系统确认仍锁屏 | 仅证明该条件下持续采集，不代替长稳或最终安装验收 |
| Mac 锁屏登录及动态桌面 | 通过所属原生窗口启用输入并单次提交已有私有凭据；本地画面核对已回用户桌面，恢复只查看。1920×1080 图案实测 **14.687 FPS**，437 次采样、0 无效帧码 | 是正式窗口合成后的实际变化像素；不是配置值或解码吞吐 |
| Mac 资源释放 | 捕获时 worker 持有 PreventUserIdleDisplaySleep 和 UserIsActive 两项断言；关窗后两项均消失，图案退出 | 不修改 pmset、锁屏或自动登录设置，不在 helper 空闲期间持续持有 |
| Linux 最新 helper 非零预算 | 正常建连后，350 kbit/s UDP policing 生效时，窗口质量状态为 `encoder_target_bps=3000000`、采集约 1.143 FPS；受限实际显示约 2.00 FPS | 受限采样保留原 >12 FPS 失败事实，不当正常性能通过 |
| Linux 解除限速恢复 | 同一视频 session 和 generation 内恢复到 `encoder_target_bps=0`、采集 15 FPS；随后实际显示 **14.533 FPS**，0 无效帧码 | 1306×768，不冒充 1080p 或跨全部硬件通过 |
| 限速真实性 | 实际命中 1452 个 UDP 包，215 包超额丢弃；测试后原 fq_codel、服务和配置恢复 | 源端口 policing，16 KiB burst；不是 RTT 整形或全机总带宽上限 |

两份实际呈现样本都沿用原 12 位帧码、互补行、颜色及单调性检查，采样频率超过 30 Hz，>12 FPS 阈值未放宽。
跨机器时钟没有直接相减；FPS 由操作端同一时钟下的真实像素变化计算。此前已通过的 Linux 新 session 首帧、90 限速恢复及普通输入不再重复。

## Mac 根因和修复

上一轮只修复“在线但不活跃”的显示器枚举/布局检查，证明能够出锁屏首帧。
本轮持续观察发现，ScreenCaptureKit 随后仍约每 12 秒报告“找不到任何要捕捉的显示器或窗口”，结束媒体流并重建会话。
输入启用曾成功维持数秒，随后随新会话回到只查看；不能将此前全部输入预检失败归因于测试按钮。

诊断时临时使用有时限的显示器唤醒保护，同一锁屏 session 连续 30 秒未中断，作为定位依据，不计产品修复通过。
本地 RustDesk `7aa98d43cf1962a7a29ec16ffef42974377ef11e` 的 `src/server.rs` 有连接时唤醒，`src/platform/macos.rs` 有会话 WakeLock；本项目参考该行为，独立使用系统 IOPM API 实现，没有复制其源码。

新增 `CaptureDisplayActivity`：已通过屏幕录制权限检查、真正创建采集时才唤醒显示器并阻止空闲熄屏；正常结束、构造失败或 worker 退出后释放所属断言。
不解锁用户、不改变电源偏好、不阻止用户主动睡眠；未增加像素复制/转换或修改鉴权、传输与输入规则。
原 App Nap 活动保护仍独立存在。只新增系统 IOKit 链接，没有额外三方依赖。

新增原生回归覆盖正常作用域释放、禁止复制、创建失败和唤醒失败回收；OS 调用由测试替身替代，不实际唤醒显示器。
Mac 以 4 个作业构建通过，暂停时停止了所属构建进程，继续后复用缓存完成；原生回归编译为单作业。
新包仍使用原固定测试路径和签名身份，没有重新申请屏幕录制/辅助功能权限，也未修改 `/Applications` 安装包。
签名后二进制哈希：`3f9f545c38d7d58013d2253e22b5556b31e8abb21344894a09137844f1c8c0f7`。

## 保留的中断和无效观察

- 用户暂停时停止构建、隔离窗口与测试，恢复原服务及限速。那轮 Linux 已观察到非零预算回默认，但恢复采样只有 169 次有效采样，窗口被关闭后报 surface ownership changed，不计 FPS 通过；继续后才取得本报告的完整恢复样本。
- 续测的一轮 Linux 出现 `desktop presentation backlog expired; restart the video generation`。这解释了视频代次结束；脚本未处理重连时 `quality=null`，报错后主动清理，因而没有完整恢复结果。随后旧连接的超时出现在清理重启原服务之后，不能据此确立另一个产品缺陷。修正脚本并等待正常链路建立后的一轮通过，前轮失败记录保留；积压退代后的完整恢复仍按原 06.2/06.5 缺项处理，不反复改传输逻辑。
- Mac 第一次新包动态样本前，普通用户的系统会话查询没有返回 root 可见的锁屏字段，夹具预检拒绝启动；误启动的采样未看到图案，是无效观察。随后由服务侧会话信息和所属窗口图像核对已登录，启动夹具后使用新文件名采样，得到本报告的有效结果；未重复提交凭据。
- 构建启动时的文件属主/过期用户上下文错误均发生于实际构建之前。核对原请求和远端状态后才刷新上下文启动；不将这些启动失败算成编译通过。

## 恢复与下一步

两次 Mac 临时服务、三次 Linux 临时服务均恢复原服务，安装文件和配置哈希未变；测试 job/timer 停用。
Mac 关窗即释放捕获断言，临时凭据副本及两平台合计 10 个运行目录已通过有界删除完成。
两个本机隔离 profile 的 Desktop/MCP 均退出，临时凭据槽删除、原槽未变；私有原始记录和 Mac 固定测试 App/构建缓存/签名包备份保留。

本轮不再把 Mac 动态 >12 FPS、Linux 最新 helper 非零预算及解除限速的同会话恢复列为待开发。
Mac 实际非零预算、RTT/路径变化、积压结束旧代次后的完整恢复及其他原清单边界仍未全部覆盖，06.x 不整体关闭。
窗口/输入、Mac/Linux 操作端、AI 异常与通知继续使用原分组；最终候选、安装升级与资源/稳定性回归单独归账。
2/8 小时仍按用户要求暂缓，没有自动启动；本轮未 push、COS 或更新本机安装版。
