# 视频消费反馈、积压回收与 Linux 采集节奏

日期：2026-10-18，基线 `bf2e919`。对应 W3/06.1～06.6 的阶段实现，完整 W3 尚未关闭。

## 产品改动

保留现有可靠流、认证和四帧在途额度。发送端在请求下一张原始画面之前检查额度和采集节奏；只有显示/消费确认返回额度之后才继续。根据实际等候额度的时间降低采集频率，健康消费时逐步恢复，最高不超过请求 FPS。一次累计确认释放多个额度时按返回的额度分摊等待，避免低估吞吐。原始画面只保留最新状态，不丢弃已编码的 H.264 参考帧。

节奏从开始采集计时，包含采集/编码耗时，避免在慢软件编码后再额外等待完整周期。反馈只使用发送端单调时钟；不直接相减跨机时间，也不把解码流水线的固有延迟等同于网络排队。

压缩帧自开始发送起若五秒未被消费，结束当前视频代次，取消该代次输入与光标。保留现有控制连接和单查看者占用，可用既有切屏/重开机制获得新关键帧。静止桌面没有未消费帧时不设这个超时，等待画面变化不被计入积压。此策略不改变现有其他业务流，也没有新增使用人数限制或配置格式。

协议字段没有增删；`fps` 文档明确为请求上限，实际变化帧数可能因静止桌面或消费压力降低。

## 自动检查

- Remote Desktop 单元 **9 项**、真实 loopback QUIC **31 项**通过。
- 新检查包括：累计/重复/未来确认边界、降速与逐步恢复、静止等待、返回额度后不突发采集、健康消费超过 12 FPS、60ms 模拟慢编码不被双重限速、四帧解码流水线延迟不造成反馈降速循环。
- 积压检查在真实流上不发视频确认但维持控制心跳；旧视频关闭后输入释放，原业务请求仍可用，其他查看者仍被 Busy 拒绝；同一 session 的 generation 增加，首帧为关键帧，旧输入/确认无效。这是传输 fixture，不是原生系统输入或真实链路限速证明。
- 已确认的静止帧等待超过五秒后仍可恢复下一张变化帧，没有重复造帧。
- 最终 Bridge 全部 **99 项**通过（17.58 秒）。编译最大同时为 Linux 4 jobs 和 Windows 4 jobs，嵌套 native 1 job。

## 保留的性能失败与对照

环境：Ubuntu 22.04、GNOME Shell 42.9、VMware 单屏 1314×704、实际刷新率 59.997314 Hz；Windows 原生 D3D11 硬解显示。使用正常账号/设备认证及独立原生诊断窗口，显示自有两分钟动画，不修改显示模式、不注入输入。动画不是高复杂度码率基准，也不是 1080p 验收。

`remote_desktop_check` 每代次预热 15 帧、测量 75 帧；扣除全部预热提交数后计算确认显示数/本机实测时长。当前检查要求超过 12 FPS 且达到所选档位的 90%，15 FPS 档即至少 13.5 FPS。

## Linux 原始采集时序修正

[GNOME Mutter 42.9 源码](https://github.com/GNOME/mutter/blob/42.9/src/backends/meta-screen-cast-stream-src.c#L543) 在重绘时检查距上一帧的最短间隔；过早则安排后续重绘。结合当前约 60 Hz 与约 12 FPS 的采集跨度，推断精确的 15 FPS 上限会因时序偏差漏过部分刷新机会；这项因果仍需下面的实机对照确认，不能单靠源码下结论。

PipeWire 协商为原始更新留每秒一帧余量；编码与发送仍受请求 FPS 限制，回调继续只保留最新原始缓冲。没有增加视频历史队列或将重复帧计为有效显示。

完整 Linux Desktop 构建及 Linux 媒体 24 项测试通过。第四轮保留第三轮 Executor，只替换隔离 Desktop 采集组件，在同一显示模式、动画和原生 Windows 显示检查下，两代次分别为 **14.3856 / 14.3593 FPS**，每代显示 90 帧，未确认呈现为 0，超过原定 13.5 FPS 门槛。74 个采集间隔分别为 5,068,232 / 5,001,449µs，并行环境查询最大 29.25 / 21.94ms。该结果支持采集时序修正对当前环境有效，不推广为所有 Mutter 版本或显示模式均已通过。

同屏重建、第二查看者拒绝、关闭后原连接环境查询均通过。原始记录在 `.build/remote-desktop/formal-linux-login-18e60ef7fd5e`，构建日志为 `linux-desktop-build/flow-capture-build.log`；静止等待单测最终复查通过，日志为 `flow-static-capture-final.log`。测试结束原服务 active、程序与配置/unit 哈希保留、用户会话仍解锁，临时进程/输入设备/目录均已清理。
