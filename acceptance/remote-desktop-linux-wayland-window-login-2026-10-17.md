# Windows 正式窗口 → Linux Wayland 锁屏密码解锁

日期：2026-10-17；Linux 实现提交 `2a740c9`。
[机器记录](remote-desktop-linux-wayland-window-login-2026-10-17.json)保存产物、
logind 状态、实际媒体进程、返回窗口状态、画面比较和清理结果。

## 已通过的产品路径

本机 Windows 使用隔离 profile 中的正式 Desktop/MCP，通过既有设备认证连接
Linux VM 556688188。只打开一个独立远程桌面窗口，随后没有手动关闭重开、
点击重连或调用 retry。Linux 使用真实 `--media-supervisor`，其普通用户 helper
通过已认证本地 IPC 服务原生采集和输入；不再只是 broker 检查包装器。

1. 窗口实际显示生成的全屏 GTK 测试图案，1280×800，GNOME Wayland 会话 23。
   启用操作后的中心点击被远端记录为一次按下/抬起，坐标约 (639.88,400.27)，
   没有把普通用户 GUI helper 的采集误认为系统 helper：进程组和父子关系已核对。
2. 测试控制器锁定该会话。原窗口自动恢复到真实锁屏时钟画面，操作状态复位为
   “仅查看”。logind 保持同一活动用户会话且 LockedHint=yes；root 导出进程
   与普通用户 capture worker 均由新的系统媒体 supervisor 管理。
3. 在窗口重新启用操作，通过原生输入表面发送 Enter，实际显示 hy 密码框。
   同时独立 VMware 控制台确认其为真实登录界面；不是锁前旧桌面的回放。
   进程检查同时看到 user input worker 和 root input-session worker。
4. 经实际密码框确认后，通过同一窗口原生键盘路径提交已有私有测试资料中的
   系统密码一次。密码不进入命令参数、源码、日志或验收文件，提交标记防止
   不确定结果时重复输入。没有使用 SSH、loginctl 或恢复脚本完成该次解锁。
5. 在清理恢复之前，logind 已变为 LockedHint=no；独立回滚定时器尚未触发，
   restored 标记不存在。窗口自动返回用户桌面，frame_ready=true，且再次
   复位为“仅查看”。旧 root 导出/输入进程退出，仅剩普通桌面的 capture。
6. 实际返回窗口截图重新显示原 GTK 图案。原生画面区域 RGB 平均绝对误差为
   (0.258,0.024,0.011)/255，与登录前吻合；没有只用连接状态代替实际呈现。

## 仍存在的问题

锁屏后等待期间，观看会话在锁状态仍为 yes 时多次自动重新建立。CDP 中已观察
到不同 session_id，且操作状态回到仅查看；因此**不能据此宣布锁屏持续观看稳定**。
可能涉及熄屏或输入/采集代次退出，但本轮没有保存足够的电源状态和退出原因，
不能把猜测写成根因。后续需要同步采集这些事件，修复后再做有等待时长的登录回归。

密码框旁的等待图标也在独立控制台出现。观察后单次密码提交确实完成解锁，
所以这轮没有证明该图标意味着输入不可用，仍不修改系统登录流程来绕过它。

首次 5 秒设备连接未完成，脚本在打开 Desktop 前退出；没有保存该次完整连接
返回值。两次 SSH 认证观察也发生超时。随后确认候选服务、supervisor 正常运行，
VM 有约 2.4 GB 可用内存、未使用交换空间；20 秒有界连接成功。未据此认定
服务崩溃或资源不足，也没有在不确定状态下重复切换服务。
