# E3 指定用户文件后端阶段记录

## 实现与边界

- 将已有文件处理从 TaskService 拆为 FileEngine，复用原读写、补丁、哈希、搜索、目录创建、复制、移动、删除及 ZIP 实现。默认服务账户入口保持原接受、配额、异步任务和记录流程。
- 内部 user-worker 增加文件路由，在已核实 UID/SID 的原生用户进程内执行文件访问；文件内容通过有大小和 SHA-256 校验的二进制帧传递，不放进控制 JSON。
- 父进程继续持有机器 SQLite 和跨任务路径锁。用户进程解析实际路径键，父进程只比较锁键，不以服务权限代替用户检查路径。服务写入、上传和用户文件工作进程共用原锁域。
- 文本发布前必须收到父进程持久化确认；批量进度同样等待确认。队列满时丢失的解锁通知会使锁保留到工作进程退出，避免过早释放。
- 取消在工作进程内协作执行；已知初始取消随请求发送，避免取消消息与删除开始竞争。通道异常先通知停止、等待清理，再由原生进程生命周期兜底。父进程异常退出等待路径同样先回收进程再释放剩余锁。

这一步完成的是后端及源码集成。公开 FileSystemRequest 尚未增加 execution，默认服务入口尚未路由至用户后端，因此正式工具还不能选择用户执行文件操作。编译时相关父端函数存在暂未使用提示，下一阶段接入公开入口后消除。

## 验证

原生集成测试 `native_user_filesystem_worker_acceptance` 使用独立的 `pab-file-acceptance-*` 用户目录：

| 环境 | 原生账户 | 结果 |
|---|---|---|
| Windows90，SYSTEM 父进程 | WTS1 Administrator | 通过 |
| Windows90，SYSTEM 父进程 | WTS2 普通账户 | 通过 |
| macOS ARM，root 父进程 | UID501 | 通过 |
| Debian Linux 无 GUI/logind 容器，root 父进程 | UID23001 | 通过 |

验证中文路径与超过 64 KiB 的文本跨二进制帧写入、分段读取、stat、SHA-256、补丁、搜索、复制、移动、ZIP 创建/解压和删除。
Unix 核对文件及目录 UID；Windows 核对文件所有者为目标 SID 或管理员组，并排除 SYSTEM。
测试还覆盖错误 expected_hash 不覆盖原文件、持有服务路径锁时用户写入返回 path_busy、初始取消不删除、服务私有目录拒绝写入，以及返回记录可读取。

新增协调中断测试：父进程确认发布前目标仍是原内容；丢弃确认后原文件不变、临时文件清理、锁释放。正常确认分支先检查 SQLite 的 committing/unconfirmed 事实，再允许发布。

- Windows 文件回归：50 项通过；路径锁筛选 3 项通过；工作进程帧编解码 1 项通过。
- macOS 文件回归：53 项通过，原生用户测试另行显式运行通过。
- Linux 文件回归：52 项通过，原生用户测试另行显式运行通过。
- `cargo check --locked -p pab-executor --tests`、三平台 Executor 编译通过。
