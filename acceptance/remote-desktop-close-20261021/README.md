# 远程桌面关闭确认修复

Windows 1.3.14 已包含本项改动并发布 COS，见[发布记录](../windows-close-release-20261021/README.md)。下文开发阶段的“未发布/暂停”描述按当时状态保留。

2026-10-21：关闭按钮原先调用未获权限的 `plugin:window|close`，将拒绝信息显示在标题栏，也没有关闭确认流程。改用仅允许远程桌面关闭自身的 `desktop_viewer_close` 命令，弹出带父窗口的系统确认框，避免原生视频遮挡 WebView 内的弹窗。取消保留连接，确认先释放当前会话再销毁窗口，原生关闭请求（包括 Alt+F4）接入同一流程；重复点击只保留一个确认请求。删除设备后的自动清理直接销毁窗口，不触发用户确认。

新增 3 项针对性界面用例覆盖中英文命令参数、取消/确认、原生关闭事件、重复请求和失败重试。首次原生事件用例在 fixture 监听器建立前发出事件而超时，补充等待初始状态后仅重跑该用例通过；其余已通过用例不重复。前端构建、Windows Rust Release 检查通过。只增加原生对话框库 rfd 0.16.0，原有依赖版本和校验和保持。

隔离运行新编译的内嵌前端程序，实际点击标题栏关闭按钮，确认原生对话框属于本窗口，显示期间父窗口禁用；点击取消后原窗口恢复可用。再向这个私有窗口发送 WM_CLOSE，确认同样弹框；点击关闭连接后窗口被销毁，对话框清理完成。远端媒体当时的状态原样写入机器记录，不将局部窗口验证外推为新的登录或全平台验收。

临时程序、测试凭据槽均已清理，原凭据未改，未覆盖本机安装版。发版按用户要求保持暂停，线上仍是 1.3.12；此前预留的 1.3.13 没有上传，恢复发布时须重新冻结包含本次修复的源码。

Mac/Linux 使用同一原生确认接口，本轮未在这两个平台实测。对话框实现参考 [rfd 原生消息框接口](https://docs.rs/rfd/0.16.0/rfd/struct.AsyncMessageDialog.html)。详见[机器记录](result.json)；原始私有日志位于 `.build/remote-desktop/viewer-close-20261021/`。
