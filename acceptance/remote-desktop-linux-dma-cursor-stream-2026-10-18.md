# Linux DMA 视频与独立光标通道接入

日期：2026-10-18，基线 `e3f70eb`。对应 W2/W5，**正式内嵌 worker 与本机通道的阶段验收，尚非完整远程窗口验收**。产物、源文件哈希和成功/失败记录见同名 JSON。交付清单仍为 9/53 完整关闭。

## 实现

复用现有受 supervisor 管理的单 exporter 连接，通过不同请求标识和独立序号串行交换视频/光标描述符。原视频请求 16 字节、元数据 64 字节保持；新增光标元数据 120 字节，只有可见光标附带两个 fd。隐藏、暂时重取、不可用分别表达，不用旧图片冒充新结果。

光标线程约每 8 毫秒尝试采样，不依赖视频帧请求或网络额度。连接锁只覆盖请求/应答，图像读取、编码及下游发送在锁外；形状不变时复用已有图像对象。当前线性光标仍需读取小图以识别同一个 framebuffer 的内容变化，不增加整屏读取。250 毫秒检查一次会话、电源和布局；[GDBusConnection 文档](https://docs.gtk.org/gio/class.DBusConnection.html) 明确支持跨线程调用，采样线程不迭代 GLib 主循环。

不支持的光标返回独立不可用状态，视频 exporter 保持；损坏或未完成的描述符交换会终止共享本地通道，避免把光标回复错认成视频。关闭时停止并等待采样线程，原生资源随采集生命周期释放。普通 PipeWire 启动失败转入 DMA 前清除尚未发布的光标错误状态。

## 检查与实机结果

- 原有视频描述符边界 **39 项**、新增光标 **38 项**均通过 ASan/UBSan。覆盖状态、几何、序号、截断/多余 fd、CLOEXEC、异常回收、80 次视频与 80 次光标并发交换，以及发送前/发送中的取消；拒绝分支无 fd 增长。
- Linux 媒体库 **24 项**通过。完整 Desktop 以 4 个 Cargo jobs、嵌套构建 1 job 构建成功，SHA256 `1c61581d5eed32b82cc70bcfb7c0a9b3f86049ad37816f7ed67e8ba8d18e107b`。
- Ubuntu 22.04 / GNOME Wayland / VMware，UID 1000，会话 299，实际单屏 1314×704。通过既有 `linux_dma_broker_check` 启动隔离 supervisor/helper，使用完整 Desktop 内嵌 worker 的正常 `capture ... desktop-separate-cursor` 入口。测试参数中的旧 `dma` 标签不决定实际来源，以 worker 输出为准。
- 普通桌面三次均选择 PipeWire，取得 24×24 光标；锁屏稳定两秒后，三次均自动选择 DRM DMA，取得 64×64 光标，热点 (4,4)。测试未直接设置显示电源状态；由正常捕获路径处理唤醒。
- 每次在请求任何编码帧前获得光标，随后解码 3 帧；发送错误光标命令使该客户端退出，视频继续，再连能取得光标。暂停消费一秒后重新读取最新状态，再解码；合计每次 5 帧。
- 普通桌面 fd 为 33→33，锁屏为 15→15；最终锁屏三次正常停止约 34–35 毫秒，光标 socket 删除，broker 无错误并回收 socket。不是长期资源平台期或帧率验收。
- 原安装程序、配置和服务文件哈希保持；原服务 active。测试进程和临时目录清理，锁屏后恢复同一会话解锁状态，恢复定时任务停止。未保存屏幕或光标像素。

## 保留的失败与待办

1. 首轮普通桌面静止，测试错误地要求连续重复帧而超时。PipeWire 静帧不持续产出是预期行为；改测试为仅在未锁屏时显示自有动画窗口，未改产品帧率行为。
2. 紧接 `LockedHint=yes` 启动的锁屏轮次在视频头之前失败，错误为 `Display did not wake`。测试夹具等待两秒后同一产品二进制通过；这支持继续排查锁屏过渡期间的唤醒时序，**尚未证明根因，也未修复产品**。不能用稳定锁屏通过覆盖该失败。
3. 尚待正式远程窗口、真实移动/形状/隐藏与输入定位、锁屏到系统登录/解锁切换、多屏及 DPI/旋转、持续性能验收。D-Bus 故障时采样线程退出延迟也需验证；本轮只证明健康环境正常停止时间。
4. X11 系统 HideCursor、Mac 源实机验证及其他清单项继续保留。
