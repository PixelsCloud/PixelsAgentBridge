## 实际修复

Mac 被控端原先将实体 VK 转为 `Key::Unicode`，再按当前输入法反查原生键码。
初次标点用例在目标观察到小键盘 `1`，斜杠也没有完整到达，最终只有分号；这不是传输 ACK 的推测。

远程桌面媒体输入现改用独立的物理键码映射：主键区数字与小键盘区分，左右修饰键区分，按下时选定的原生键码仍保留到释放。
变更只涉及 `MacMediaInput`；既有浏览器/普通输入的 `map_virtual_key`、账号鉴权、通用传输和输入协议未改。
Mac 操作端原先通过的 11 项继续复用，只补测受影响的标点和未执行的右 Shift；Apple 目标端另测两项标点回归。

两项映射回归测试与 Mac 完整 release 构建通过。提交前仅进行无语义的 Rust 格式化，没有重跑功能矩阵。
Windows/Linux 生产路径未受本次映射变更影响，复用其既有构建。

## 保留的失败与判定修正

- **Mac 修复前标点失败**原样保存，修复后的受影响用例单独记录，没有覆盖原结果。
- **Linux 初次中文用例**只有候选、没有最终文本，不记通过。后续本地单个空格对照证明输入法可以提交；窗口键事件对照及逐键前台检查下的实体键两项通过。此前另一次准备阶段因本机 `cyber_desktop.exe` 成为前台而被守卫拦截，未发送测试键。初次失败的根因没有完整定位，不据此声称修复了 Linux 产品故障。
- **Linux 右 Shift 抬起快照**初次采到在途状态；同一输入稍后已释放，未重发。保留初次记录，不宣称验证了 250 ms 内释放。
- **Mac→90 的首项中文判定**曾因私有脚本按 Windows 本地编码重写中文预期而失败；原目标哈希已是正确的“你好世界”，只修正判定，未重复输入。
- **Ctrl+Backspace**在标准 WinForms 编辑框留下 DEL，不能证明所有应用的按词删除。该失败保留，左右 Ctrl 的验收改用原生支持的选区组合。
- 旧 Apple 首击观察继续保留在[上一批记录](remote-desktop-window-input-assistance-2026-10-20.md)，本次完整前提下的 `(100,100)` 不改写旧结果。

当前协议发送实体键，远端输入法完成组词。**本地 IME 成文文本直接转发仍不支持**，不将其伪装成已实现，也不自动扩大首版开发范围。
系统保留快捷键、其他目标应用、动态布局与未覆盖故障组合仍按原 LT 条款记录，不重跑本批已通过的条件。
