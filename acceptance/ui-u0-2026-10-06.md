# 控件自动化 U0 原型验收

此报告只覆盖库与隔离方式原型；四个正式 MCP 工具尚未接入，不能视为产品验收。

## 库与依赖

- Windows：`uiautomation =0.25.1`，Apache-2.0，crates.io 发布日期2026-09-04。
  `windows =0.62.2` 官方绑定。仅开启 pattern 无法编译，库 core 引用了未启用的
  input 模块；加入 input 后还需显式补 Win32_UI_WindowsAndMessaging feature。
  产品只用控件接口，键鼠继续用已有 Enigo。专用线程显式初始化 MTA，再用
  `UIAutomation::new_direct()`，所有 COM 对象先析构，最后 CoUninitialize。
- macOS：`accessibility =0.2.0`、`accessibility-sys =0.2.0`，MIT/Apache-2.0，
  crates.io 发布日期2025-03-22；`core-foundation =0.10.1` 与封装依赖一致。
  ARM 实机 Rust 1.95 编译通过。高层接口只覆盖部分 AX，缺失处可用同库底层绑定。
- 独立原型清单及锁文件位于 `acceptance/probes/ui-libraries`。
  产品最终依赖图、安装包体积差异及 Intel 编译留待 U3/U6，不宣称已验证。

## 真实应用结果

使用本仓库 WinForms/AppKit 自建测试窗口，操作发生在普通文本框和按钮；
应用自身写出的结果文件确认值为 `PAB 中文🙂`，按钮计数为1。未对真实用户文档派发动作。

| 检查 | Windows 本机 | Mac 603527578 |
|---|---|---|
| 找到窗口内输入框、复选框、按钮 | 通过 | 通过，9个节点 |
| 写入中文/Emoji并读回 | 通过 | 通过 |
| Invoke/AXPress实际计数 | 1 | 1 |
| Provider主线程阻塞10秒 | 查询进程超时2秒被杀并回收 | AX调用约0.7秒失败，错误-25204 |
| 应用恢复后再次查询 | 通过 | 通过 |
| 签名应用委托子进程查询 | 不涉及TCC | 通过 |

Windows fixture 由隐藏 PowerShell 启动时，窗口初始不可见；测试明确显示自建窗口后查询。
Mac fixture 必须保留 NSWindow/target 生命周期，运行 AppKit 事件循环。

Mac 原型以原有固定免费证书及 `vip.rgaa.pab.desktop` 标识签名，放在源码 `.build`
目录，通过 LaunchServices 启动；没有替换已安装应用，没有重置 TCC。
直接由命令进程启动的裸二进制曾返回权限错误-25211，不能将其结果当正式应用权限状态。
签名应用及其直接派生子进程均查询成功，但正式 helper 的派生链仍须 U3 安装验收。

排查期间 Mac 屏幕休眠，只显示屏保壁纸，AXWindows 返回了异常的 AXApplication 根；
Apple C 接口与 Rust 库结果相同。唤醒后返回 AXWindow 和完整 fixture 控件，实际读写通过。
产品需识别不可交互会话/异常窗口根，不把这些情形当空树成功，也不一概报“未授权”。

## 隔离决定与剩余验证

采用现有 desktop 可执行文件的内部 `--ui-worker` 模式，在可回收子进程里持有所有 UIA/AX
对象。不新增安装产品、不承载网络连接、不复用多个 MCP 的连接。父进程有界串行请求，
工作进程无响应时终止并回收，令其元素引用失效；不创建无限替补线程。
动作结果不确定时绝不自动重放。wait 在 Executor 采样，不在 helper 中长期占用输入队列。

U0 原型证明可行性。仍需产品级 watchdog、工作进程崩溃/签名归属/会话切换/多 MCP
隔离、资源上限、取消与不确定动作等测试，不能以本报告代替这些测试。

原始日志保留在两端 `.build` 下，不提交桌面内容。Windows fixture 已通过 stop 文件关闭；
Mac awake1 fixture 同样已发出 stop，fixture 另设5分钟自动退出。
