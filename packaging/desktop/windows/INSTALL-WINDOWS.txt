Pixels Agent Bridge - Windows Debug test package

1. Extract the entire ZIP to a local folder. Keep all files together.
2. Open PowerShell as Administrator in the extracted folder.
3. The installer enables service-generated Ctrl+Alt+Delete automatically if
   SoftwareSASGeneration does not already allow services (value 1 or 3).
   This changes the Windows machine policy to value 1. If the policy cannot be
   changed, installation continues with a warning; remote Ctrl+Alt+Delete may
   remain unavailable. Other installation and connection functions continue.

4. Install the complete package, replacing the URLs with
   values supplied by the deployment administrator:

   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -ControlUrl 'wss://<server>/control' -RelayUrl 'https://<relay-server>'

5. Open the single desktop app:

   powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:ProgramFiles\PixelsAgentBridge\run-app.ps1"

   The NSIS setup.exe opens this window automatically after installation.
   Both NSIS and ZIP installation also enable automatic desktop window startup
   for every Windows user at sign-in. After a reboot, the background service
   starts before sign-in; the visible desktop window opens after sign-in.
   Reinstalling or upgrading refreshes the same startup shortcut. Uninstallation
   removes it. Starting the app again restores the existing window in that session.
   The command above is for manual ZIP installation or reopening the app.

   The overview shows this machine's 9-digit device code and temporary
   password. On another machine running the same package, use Remote Connection
   to enter that code and password.

6. Check the background components if the device is not reachable:

   Get-Service PixelsAgentBridgeExecutor
   Get-ScheduledTask PixelsAgentBridgeSessionSupervisor

The installer requires administrator rights and outbound access to the HTTPS
Relay and WSS control server. It installs a LocalSystem service and a SYSTEM
session supervisor. Run the installer from a complete Debug ZIP after each code
change. Do not replace individual files in an existing installation.

The installer's local access token belongs to the Windows account that runs the
elevated installer. If UAC uses a different administrator account, that account
gets local device access; another signed-in user needs a separate local access
grant. Uninstallation removes program files and services but retains device
identity, password, and task data.

Installation diagnostics (EXE and ZIP)
------------------------------------
The EXE requests administrator authorization through Windows UAC. If UAC is
cancelled, Windows does not start the elevated installer; no installer log can
be recorded for that attempt. The ZIP scripts require an already elevated
PowerShell window and report an error if it is not elevated.

Each installation or removal attempt saves its own diagnostic files under:

  %ProgramData%\PixelsAgentBridge\logs\setup\

If this directory is not writable, diagnostics fall back to:

  %TEMP%\PixelsAgentBridge-InstallerLogs\

The installer prints the actual path in its details and includes it in failure
dialogs. The .log file records UTC timestamps, installation stages, relevant
Windows/child-process error codes and PowerShell exceptions (UTF-16 LE).
Its .log.powershell.log companion records PowerShell output and native command
output. PowerShell 5.1 writes this transcript as UTF-8 with a BOM. EXE failures
before PowerShell starts have only the first file.

Successful retries and removal retain previous attempts. Historical PowerShell
failures also append to logs\install-error.log or logs\uninstall-error.log under
%ProgramData%\PixelsAgentBridge; these files are no longer cleared on success.
These logs contain local paths and account names; review before sharing. The
installer does not intentionally log device passwords, access keys or the
contents of configuration files. Old diagnostic files can be removed manually
after troubleshooting. Do not remove the rest of the machine data directory.

If another Pixels installer or uninstaller is active, interactive EXE setup
offers to end previous setup processes and force the upgrade. For unattended
recovery, run the EXE with /S /FORCE. Recovery verifies the previous process's
Pixels installer version resources, excludes this setup and its launchers,
then ends the previous setup and its already spawned helpers before retrying
the lock. It does not run the previous uninstaller. Device identity, password,
configuration and task data are retained. If another process still holds the
lock, setup reports the conflict instead of running two writers concurrently.

An unusable legacy lock falls back to the new machine-wide setup coordinator.
New installers and uninstallers still exclude one another. Native installation
commands have a 60-second deadline (service stop/start requests: 15/20 seconds).
Stopping an unresponsive service escalates to ending its verified executable
process. Browser/document runtime processes belonging to this installation are
also stopped before replacement. Corrupt packages, denied administrator access,
full disks and unrecoverable Windows failures produce an error; forced upgrade
does not bypass Windows security or pretend that installation succeeded.
