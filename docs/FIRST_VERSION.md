# 功能与使用说明

> **注意：** 我们提供免费 Relay 服务，如果想获得更快的速度，请您自行部署 Relay 服务。

更新日期：2026-10-29；新增功能对应客户端 1.3.40。

第一版的功能开发已完成。本文按当前仓库实现说明安装、Agent 接入、远程操作与自部署，不再使用早期开发计划中的待办列表描述产品。各平台安装包统一在同一个 GitHub Release 提供；已有安装版是否包含某项功能，以对应发行包为准。历史验收只说明其记录的版本与环境，不表示所有系统、驱动和权限组合均已验证。

## 产品组成

| 组件 | 作用 |
| --- | --- |
| Desktop | 操作端界面，管理设备、账号、文件传输、终端、远程桌面、任务记录和 MCP 连接；也可展示本机被控信息 |
| Executor | 目标计算机的后台服务，接收已认证的远程操作；关闭 Desktop 不等于停止 Executor |
| MCP | 在 AI Agent 所在计算机运行，提供设备、命令、文件、界面、文档等工具 |
| Android 应用 | 手机被控端，在 Android 授权范围内接收操作 |
| 管理平台 | 控制服务、Web 后台与 PostgreSQL，负责账号、设备发现、认证和 Relay 管理 |
| Relay | 无法直接建立 P2P 时承载中继数据，可部署多个节点 |

管理平台、Relay 和客户端保留各自的组件版本，统一放在同一个 GitHub Release 下载，组件版本号不要求相同。两端需要使用配套且兼容的服务和协议。

## 平台与边界

| 平台 | 安装形态 | 使用范围 |
| --- | --- | --- |
| Windows | x86_64 桌面安装包 | Desktop、Executor、MCP、远程终端、远程桌面 |
| macOS | Apple Silicon／Intel 对应安装包 | Desktop、Executor、MCP、远程终端、远程桌面；屏幕与输入需要系统授权 |
| Linux 桌面 | Ubuntu 22.04 x86_64 DEB | 原生 Desktop、Executor、MCP、远程终端和目标环境支持的桌面采集／输入 |
| Linux 无界面 | x86_64，glibc 2.31+ | Executor、MCP、命令、终端、文件等基础工具，无需图形会话；不提供桌面画面 |
| Android | Android 9+ APK | 手机被控端；提供系统允许的界面、文件、应用、通知、文档、命令与网络操作，不提供 Desktop／MCP 操作端 |

Linux 桌面包与无界面包是不同发行目标。能在 Wayland 上打开操作端，不代表任意 Wayland 合成器都允许采集、输入或操作登录画面。macOS 的屏幕录制、辅助功能和文件访问由系统分别授权；普通用户桌面、登录窗口和首次授权提示也可能有不同条件。

Android 命令在应用自身身份下执行，不是 Root 或 ADB shell；文件访问限应用工作区与用户授权目录。Android 浏览器自动化、Office 版面渲染和桌面特有管理能力不计入已支持范围。具体规则见 [Android 说明](../apps/android/README.md)。

## 安装与第一次连接

1. 从[统一 GitHub Release](https://github.com/PixelsCloud/PixelsAgentBridge/releases/latest)下载对应平台和架构的安装包。操作端安装 Desktop；目标计算机运行 Executor，手机运行 Android 应用。
2. 使用同一个控制服务。在发起操作的 Desktop 登录账号；被控计算机可不登录账号，以后台服务运行。
3. 在目标应用查看九位设备码和设备密码，在操作端添加设备并成功连接。登录账号不能代替设备密码。
4. Desktop 启动后自动配置检测到的受支持 AI Agent。新建 Agent 会话或重启对应客户端加载 MCP，然后交代任务。

例如：

> 用 Pixels 连接设备 123456789，检查操作系统、磁盘剩余空间和主要进程，先报告结果。

设备凭据由当前操作端用户保存，Desktop 与同一用户、同一服务下的 MCP 共享。每个 MCP 仍独立维护自己的运行连接，Desktop 不代理 Agent 的命令和传输。多个 Agent 操作同一设备时，应协调对同一文件、终端或界面的修改。

Windows、macOS、Linux 桌面安装默认配置登录后启动桌面窗口；后台服务与窗口的生命周期独立。Android 尽可能恢复用户此前开启的连接，但仍受系统和厂商后台策略约束，不会在开机时自动启动屏幕采集。

### Linux 无界面安装

使用已发布的 Linux 发行包时，可执行：

```sh
curl -fsSL https://agent.rgaa.vip/install.sh | bash
```

安装器检查发布签名和校验和，升级保留已有配置与设备数据。自建服务编辑 `/etc/pixels-agent-bridge/config.toml`，再重启服务：

```toml
control_url = "wss://control.example.com/control"
relay_urls = ["https://relay.example.com"]
```

```sh
sudo systemctl restart pixels-agent-bridge-executor.service
sudo /opt/pixels-agent-bridge/run-executor.sh show-access
```

`show-access` 显示本机设备码和密码。若在这台机器上运行 AI Agent，手动将 `/opt/pixels-agent-bridge/run-mcp.sh` 注册为 stdio MCP，并以 Agent 的普通用户运行；不要共用 root Executor 的身份库。容器和无 systemd 环境见 [Linux 安装说明](../packaging/desktop/unix/INSTALL-LINUX.txt)。

## AI Agent 自动接入

支持自动配置 Codex、Kimi Code、Claude Code、DeepSeek Harness 和 OpenCode，其中 Kimi Code 需 2.x 或以上。Desktop 每次启动检查当前用户已安装的客户端：

- 未安装的跳过，不代为安装，也不创建其配置。
- 已正确配置的跳过；属于 Pixels 的旧安装路径可自动更新。
- 合并 Pixels 配置并保留其他 MCP 和用户设置；同名第三方服务或损坏的配置不覆盖。
- 用户在「设置 → AI Agent」主动关闭后保持关闭；仍可手动启用或修复。

偏好使用用户数据目录下的 `agent-integrations.toml`。后安装的客户端在下次启动 Desktop 时检测；已有 Agent 会话可能需要重启或新建会话才能加载。设置页显示「已配置」不等于已经建立运行连接，实际会话在「MCP 连接」页查看。

其他 MCP 客户端及 Linux 无界面版采用手动注册。配置规则见[配置参考](CONFIGURATION.md#自动接入-ai-agent)，客户端开发入口见 [Desktop README](../apps/desktop/README.md)。

## 功能与操作流程

### 命令与远程终端

Agent 可以运行命令、查询任务状态、读取输出和取消支持取消的任务。手动操作时，在设备菜单选择「远程终端」，打开独立交互窗口；Windows 另提供 System 终端入口，按目标环境与执行权限使用。

运行命令时使用目标设备的操作系统与可用 Shell。目标是 Windows 不代表支持 Linux 命令，Android 也不具有完整 Linux 管理权限。目标 Shell 自身可能保存命令历史。

### 文件、文档和系统工具

- 文件：目录、属性、读写、搜索、哈希、复制、移动、删除、压缩及解压；上传下载可通过后台操作状态跟踪。
- 文档：打开、读取、搜索、提取表格、渲染支持的格式及离线 OCR，具体格式与平台差异见[文档工具说明](DOCUMENTS.md)。
- 系统：资源、进程、网络、日志、应用及受支持的系统服务操作；开发工具包括目标环境可用的 Git、Docker 与 TCP 端口转发。

某一工具出现在 MCP 中，不代表每个平台支持它的全部动作。以目标上报的能力、已安装程序、系统权限及实际错误为准。

### 独立文件传输窗口

在设备菜单选择「文件传输」，无需先打开远程桌面。窗口左侧是本机，右侧是目标设备；多个设备使用不同标签页。

1. 分别打开源目录和目标目录。路径使用面包屑，长路径缩略中间部分；点击编辑图标可输入路径，路径右侧下拉框可选择磁盘和常用目录。
2. 在本机选中文件或文件夹后点击「发送」，写入右侧当前目录；在远端选中后点击「接收」，写入左侧当前目录。
3. 下方传输任务分别显示进度、速度、用时、项目数和状态。按任务状态暂停、继续或取消；「详情」可筛选状态并翻页查看项目。
4. 同名文件默认询问，可选择「替换」「跳过」或「保留两者」。勾选「对本次传输后续所有冲突应用此选择」后，仅当前传输批次沿用该选择；其他批次仍会询问。冲突处理完毕后，冲突详情窗口会自动关闭。
5. 用「清理已完成」清理已确认完成的传输记录（可包含跳过的项目）；失败或尚未完成的任务保留，已传输的文件不会删除。目录工具栏提供搜索、隐藏文件、刷新和新建文件夹等操作。

本机使用启动 Desktop 的当前用户。远端计算机使用可用的已登录桌面用户；无法取得该用户时提示登录／解锁，不静默改用后台服务身份。Android 使用应用自身 UID，按应用工作区与系统授权目录的权限操作，不要求 Windows 式 Console 用户。远端设备名后显示实际 P2P／Relay 路径及可用的延迟信息。

### Android 文件与终端窗口

从电脑 Desktop 的设备菜单打开手机的「文件传输」或「远程终端」。终端命令在应用自身身份下运行，使用 `/workspace` 等实际可访问的工作目录；系统选择器授权的目录通过文件工具访问，不能直接当作终端中的 POSIX 工作目录。手机不提供 Windows System 终端；目标未支持的能力会显示暂无此功能或相应的权限提示。

### 远程桌面

在设备菜单选择「远程桌面」，打开独立窗口：

1. 默认只查看，确认目标后点击「启用操作」发送鼠标和键盘。
2. 标题栏切换目标显示器，选择 15／30／60 FPS 上限（默认 30 FPS），进入或退出全屏。鼠标位置由操作端本机指针即时显示，远端同步指针样式和点击热点。
3. 需要时打开统计信息，查看连接路径、媒体与输入状态；统计面板不代替实际画面或性能验收。
4. 启用操作并打开剪贴板同步后，在当前操作的查看窗口同步文字和图片。图片使用 PNG 无损压缩，保留透明度；文件和富文本不属于图片同步，请用文件传输窗口传文件。
5. Windows 提供 Ctrl+Alt+Delete 按钮。锁屏、登录与安全桌面需要已安装的辅助服务及系统条件，并仍需合法的系统登录方式。

同一台被控设备同时只允许一个远程桌面查看者。若已有会话，会提示是否强制接管；明确确认后原查看者被断开，新查看者接管。取消则保留原会话。旧版本未提供接管能力时，需关闭原会话或升级被控端；接管不绕过设备认证、系统登录或权限要求。

复制截图或图片后，聚焦远程画面，在目标应用的可粘贴区域执行粘贴；反向复制图片也使用同一剪贴板同步功能。单张 PNG 上限为 32 MiB，解码像素数据上限为 64 MiB。超限、能力不支持或同步失败会显示提示，不能将提示失败当成已粘贴。Android 暂不提供此桌面图片剪贴板能力。

桌面数据沿用已认证的连接与可靠传输；优先 P2P，必要时中继。15／30／60 FPS 是请求上限，实际帧率取决于动态画面、采集、编解码、网络和显示能力，并非固定帧率保证。

切屏、DPI、旋转、锁屏及用户会话变化会影响采集和坐标。遇到画面不可用或输入未就绪时，先检查目标会话和权限，不将「设备在线」等同于「桌面一定可操作」。

### Agent 请求人工协助

Agent 无法判断或处理界面时，可用 `pab_desktop_assistance` 向当前操作端 Desktop 请求协助。用户打开或聚焦目标远程桌面，按需启用操作，处理后明确点击「完成协助」，Agent 再复核结果并继续。

打开窗口、关闭窗口、断线都不代表协助已完成。Desktop 与 MCP 需要属于同一用户和同一操作端环境。协议、超时与取消规则见[人工协助说明](REMOTE_DESKTOP_ASSISTANCE.md)。

### 浏览器自动化

浏览器工具操作 Pixels 自己启动的 Chrome／Edge 与独立资料目录，不接管日常浏览器。首次使用需要目标机器具备相应浏览器和交互桌面。遇到登录、扫码或二次验证，使用浏览器工具自身的人工交接流程，由用户完成后继续；它与通用远程桌面协助是不同流程。

浏览器资料留在目标设备。使用条件和会话恢复见[浏览器工具说明](BROWSER_AUTOMATION.md)。

## 账号、服务与数据

账号识别发起操作的人，设备码和密码验证目标设备。启用 GitHub 登录的实例可使用 GitHub 登录，已有账号也可按设置绑定；自部署配置自己的 GitHub App。

自有程序配置统一使用 TOML。源码不包含私有部署地址；本地构建可从忽略的 `.env/client-defaults.toml` 编译默认服务，安装配置与设置页保持空值，不回显默认地址。用户填写完整的控制与 Relay 地址后覆盖默认服务。

Desktop 设置页修改当前用户的操作端地址，本机 Executor 使用安装 TOML。更换控制服务后需要在目标服务重新登录或注册；账号不会跨服务迁移，设备列表、身份和任务数据按服务隔离。仅修改 Relay 不清除账号。保存后按提示重启相应进程。

任务记录和设备凭据保存在本地；控制服务不作为任务正文或桌面录像存储。升级保留程序配置和设备身份，不以清除用户数据解决更新问题。各平台配置路径与切换规则见[配置参考](CONFIGURATION.md)。

## 自部署与 Relay 运维

部署管理平台、PostgreSQL 和至少一个可达 Relay，配置域名、TLS 与端口，再让操作端和目标端连接配套服务。完整步骤见[部署指南](WEB_DEPLOYMENT.md)与 [Docker Compose 说明](../packaging/docker/README.md)。

多 Relay 节点可在后台查看机器 IP、连接与健康状态，设置节点容量，执行维护、停用和恢复。维护有过渡期；停用需要节点实际停止接入和转发、清空中继连接并回报确认，不能只修改页面状态。节点失联时不能把旧连接数当成当前实况；已有健康 P2P 不因中继停用而被强制断开。操作细节见 [Relay 运维说明](RELAY_CLUSTER_OPERATIONS.md)。

自建 Relay 可使用自有 CA，但客户端必须信任对应公钥证书，仍校验证书链和主机名。内置发行者 CA 不替代用户自己的部署配置。私钥不进入 Git 或客户端安装包。
